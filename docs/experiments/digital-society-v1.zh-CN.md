# Atoll 数字社会实验室：第一期实验计划

状态：第一期可运行交付（模型 v1.1）  
实验代号：`digital-society-v1`  
实验规模：100 名居民的小镇社会  

## 1. 文档目的

本文档定义基于 Atoll 构建第一个数字社会实验所需完成的工作、实验目标、参与方式、最终交付物和验收标准。它同时作为产品范围、技术实施和实验设计的共同基线。

第一期不是制作一段预设动画，也不是让一群大语言模型自由聊天。我们要交付一个能够真实运行、暂停、干预、重放、比较和导出数据的社会演化实验环境。

## 2. 实验目标

第一期研究问题为：

> 当基础资源逐渐紧张时，政府透明度和再分配政策如何影响社会的合作、分裂、平等、生产和危机恢复能力？

具体目标如下：

1. 建立一个由居民、家庭、企业、市场、政府、媒体和社会关系组成的最小社会。
2. 让社会能够在没有人工逐步编排的情况下持续演化。
3. 让居民根据资源、需求、经历、信任和有限信息作出决策。
4. 让制度通过明确规则影响居民和组织，而不是通过隐藏的提示词影响结果。
5. 对相同初始条件下的不同制度进行可重复的对照实验。
6. 从宏观指标回溯到造成变化的具体人物、交易、政策和传播事件。
7. 验证 Atoll 是否适合作为数字社会的身份、组织、通信、历史和恢复底座。

### 2.1 第一阶段假设

第一版采用以下可被后续实验推翻或修改的假设：

- 居民具有生存、安全、财富、归属、地位和公平感等有限需求。
- 居民只能根据自身经历、关系网络和可接触的信息作出决定，不拥有全局视角。
- 长期稳定的互惠会提高信任，欺骗、失约、失业和政策不透明会降低信任。
- 信任影响交易成本、合作概率、信息采纳和制度支持。
- 政府通过税收、福利、公共服务、信息公开和规则执行影响社会。
- 企业根据需求、成本、资金和劳动力进行招聘、生产、定价、裁员或退出。
- 媒体影响信息可见性和观点传播，但不直接修改居民的最终决定。
- 资源冲击由固定随机种子产生，以保证不同制度组之间可公平比较。

这些假设必须在实现中显式配置，并在界面和数据导出中可以被审查。

## 3. 不属于第一期的目标

第一期明确不追求：

- 对现实国家或特定人群作精确预测；
- 复刻完整宏观经济学、人口学或政治学模型；
- 把实验结论直接解释为现实政策结论；
- 让每一个居民都由大语言模型驱动；
- 模拟战争、国际贸易、宗教、完整司法系统和复杂金融市场；
- 将实验结果包装成已经被证明的社会科学规律；
- 追求超大人口规模或分布式跨节点运行。

第一期的价值是建立一个可解释、可重复、可扩展的实验骨架，并验证一条完整的研究工作流。

## 4. 为什么使用 Atoll

Atoll 提供社会模拟所需的基础机制：

| 社会概念 | Atoll 机制 |
|---|---|
| 个人和组织 | actor |
| 家庭、公司、社区、政府 | channel |
| 群体边界 | channel membrane |
| 身份和社会角色 | actor identity、principal、membership |
| 社会行动 | request、event、response |
| 历史 | 每个 channel 的只追加账本 |
| 私有状态和公共资源 | actor state、channel resource |
| 周期性行为 | durable timer |
| 组织之间的接口 | peeractor、svcactor |
| 组织创建和成员变化 | channel/member system words |
| 故障隔离和恢复 | actor unit、desired-to-actual convergence |

Atoll 只负责“事实如何发生、被谁发出、进入哪个组织、怎样被保存和恢复”。社会模型负责“这些事实在社会语境中意味着什么”。两层不能混在一起。

## 5. 第一版社会模型

### 5.1 初始世界

默认世界包含：

- 100 名居民；
- 若干家庭；
- 8 至 12 家企业；
- 一个商品和劳动力市场；
- 一个政府；
- 一个媒体系统；
- 一张居民社会关系图；
- 食物、住房、货币、健康和信息五类核心资源；
- 至少 10 个模拟年，每年 365 个逻辑日。

具体数量作为场景配置，不写死在运行时中。

### 5.2 居民状态

每名居民至少具有：

- 年龄和生命周期；
- 家庭与组织归属；
- 财富、收入和负债；
- 就业状态；
- 食物、住房和健康状况；
- 风险偏好；
- 对其他居民和组织的信任；
- 对政府和制度的支持程度；
- 若干可变化的社会观点；
- 有限记忆和最近重要经历；
- 当前行动策略。

### 5.3 社会行为

第一版至少支持：

- 求职、招聘、工作、领取工资和失业；
- 商品生产、定价、购买和消费；
- 税收、福利和公共服务；
- 储蓄、贫困和企业破产；
- 社会交往、信任更新和信息传播；
- 投票或表达制度支持；
- 在不同社区或组织之间迁移；
- 居民出生、衰老和死亡的简化生命周期；
- 外部资源冲击；
- 政策实施及其延迟影响。

### 5.4 对照实验

第一期默认运行四个世界。它们使用相同人口、资源、行为参数、随机种子和外部冲击，仅改变制度变量。

| 实验组 | 政府透明度 | 税收和福利 | 主要观察点 |
|---|---:|---:|---|
| A | 高 | 低 | 透明但再分配较弱的社会 |
| B | 低 | 低 | 不透明且再分配较弱的社会 |
| C | 高 | 高 | 透明且再分配较强的社会 |
| D | 低 | 高 | 福利较强但制度不透明的社会 |

所有制度参数必须配置化。上述分组是默认实验，不是写死的产品限制。

## 6. 技术实现范围

### 6.1 社会运行组件

计划实现以下领域 actor 或等价运行组件：

| 组件 | 职责 |
|---|---|
| `simulation-clock` | 推进逻辑日期，支持暂停、单步和加速 |
| `experiment-controller` | 创建世界、启动实验、施加干预、终止和导出 |
| `citizen` | 执行居民决策；必要时一个 actor 可代表一个居民群体 |
| `household` | 汇总家庭资源、消费和照护关系 |
| `firm` | 招聘、生产、定价、支付工资和退出 |
| `market` | 劳动力和商品撮合，执行交易 |
| `government` | 税收、福利、公共服务、政策和支持率 |
| `media` | 新闻生成、传播范围、失真和注意力分配 |
| `social-network` | 维护社会关系图和传播路径 |
| `metrics` | 计算并发布宏观、组织和个体指标 |

最终组件边界可在实现设计阶段调整，但职责不能被隐藏在一个不可解释的全局循环里。

### 6.2 模拟时间

实验必须使用逻辑时间，不能直接把操作系统墙钟当作社会时间。

逻辑时间必须支持：

- 开始和暂停；
- 单日推进；
- 多倍速推进；
- 明确的日、月、年边界；
- 相同输入和种子下的确定性顺序；
- 记录政策和冲击的生效时间。

Atoll timer 可用于可靠唤醒，但社会时间语义由 `simulation-clock` 负责。

### 6.3 经济与资源一致性

货币和资源转移必须由领域账本统一执行，不能依赖两个无关联的状态写入。

每次交易至少拥有：

- 全局唯一的交易 ID；
- 发起者、接收者和发生时间；
- 资源类型和数量；
- 请求、提交或拒绝状态；
- 幂等检查；
- 守恒检查。

资金不得因为重复消息、actor 重启或中途失败而凭空产生或消失。

### 6.4 社会关系图

Atoll channel 适合表达组织层级，但社会关系、贸易和信息传播是图结构。第一期需要由领域组件维护显式关系图，而不是把所有关系强行表示为父子 channel。

至少支持：

- 居民之间的信任边；
- 家庭、雇佣和社区关系；
- 媒体到居民的信息传播边；
- 关系强度随互动变化；
- 从关系图计算聚类、隔离和极化指标。

### 6.5 可复现性

每次实验必须保存：

- 场景配置版本；
- 行为模型版本；
- 随机种子；
- 制度参数；
- 所有外部干预；
- 构建版本；
- 起止逻辑时间；
- 最终指标和异常信息。

相同版本、配置和随机种子应产生相同的实验结果。若存在有意引入的非确定性，必须被明确标注。

## 7. 可视化控制台

最终用户通过本地浏览器使用实验室，不要求直接读取 SQLite 或原始消息日志。

### 7.1 实验控制

控制台至少提供：

- 创建和选择实验；
- 开始、暂停、继续和停止；
- 单步推进一天；
- 调整模拟速度；
- 重置到初始状态；
- 选择制度组；
- 施加资源或政策冲击；
- 导出实验数据。

### 7.2 宏观视图

至少展示：

- 当前逻辑日期和人口；
- 就业率和社会总产出；
- 财富分布和 Gini 系数；
- 贫困率；
- 平均社会信任；
- 政府支持率；
- 观点极化指数；
- 企业数量、出生和死亡；
- 税收、福利和财政余额；
- 社会从资源冲击中恢复所需时间；
- 关键事件时间线。

### 7.3 个体和因果追踪

用户应能选择一名居民，查看：

- 当前状态；
- 家庭、工作和组织关系；
- 财富和健康变化；
- 信任与观点变化；
- 近期重大经历；
- 重要决策及其输入因素；
- 相关交易和消息；
- 生命周期时间线。

宏观图表上的异常变化必须能够回溯到相应时间段的政策、交易、企业和居民事件。第一期不承诺自动证明严格因果关系，但必须提供足够证据供研究者检查。

### 7.4 实验比较

用户能够选择两个或四个实验组，在相同时间轴上比较核心指标，并查看制度差异何时开始产生明显影响。

## 8. 实施过程中由开发代理负责的工作

开发代理负责从设计到验证的完整工程交付，包括：

### 8.1 研究和设计

- 继续审查 Atoll 的 actor、channel、timer、resource、peer 和恢复机制；
- 确定社会领域层与 Atoll core 的边界；
- 编写社会消息词汇和状态结构；
- 定义行为规则、实验参数和指标公式；
- 识别需要修改 core 的地方，并优先寻找不修改 core 的实现方式；
- 记录关键假设、取舍和已知限制。

### 8.2 工程实现

- 实现社会运行组件；
- 实现场景配置和加载器；
- 实现逻辑时钟和实验控制；
- 实现交易账本、幂等和守恒检查；
- 实现社会关系图；
- 实现统计和数据导出；
- 实现本地可视化控制台；
- 提供一条命令启动完整实验环境；
- 保持实现符合 Atoll 已有分层和架构约束。

### 8.3 测试和验证

- 为行为规则和指标编写单元测试；
- 为交易、时间、生命周期和恢复编写集成测试；
- 验证固定种子的可复现性；
- 验证货币和资源守恒；
- 验证暂停期间状态不变化；
- 验证死亡或退出的 actor 不再行动；
- 验证政策只在规定时间后生效；
- 验证异常或重启不会静默篡改历史；
- 运行默认四组实验并生成基线结果。

### 8.4 文档和交付

- 维护实验设计文档；
- 编写安装、运行、配置和排障说明；
- 说明每个指标的计算方式；
- 说明模型假设和不能支持的结论；
- 提供默认场景与示例干预；
- 生成第一份四组制度对比报告。

在实施过程中，开发代理应主动推进正常的工程决策；遇到会改变研究问题、价值判断或实验解释的选择时，提交给研究负责人确认。

## 9. 研究负责人需要参与的工作

研究负责人不需要编写代码，主要负责以下决策：

1. 确认或修改第一期研究问题。
2. 审核居民动机、制度行为和信任变化等关键假设。
3. 确认默认四个实验组是否符合研究意图。
4. 确认哪些简化可以接受，哪些因素必须进入第一期。
5. 在阶段演示中判断社会行为是否具有直觉上的合理性。
6. 对实验结果提出问题，决定后续需要增加的干预和对照组。
7. 审核最终报告中的结论是否超出模型能够支持的范围。

开发代理为每个需要确认的选择提供推荐默认值、替代方案和影响说明。若研究负责人暂未选择，则可以使用文档中的默认方案继续实现可逆部分。

## 10. 实施阶段与阶段产物

### 阶段 0：实验规格冻结

工作内容：

- 确认研究问题、核心假设、实验组和指标；
- 确定第一版社会规则；
- 定义消息词汇、状态和逻辑时间；
- 形成可执行技术设计。

阶段产物：实验规格、领域协议和验收样例。

### 阶段 1：无界面的确定性社会内核

工作内容：

- 实现逻辑时钟、居民、企业、市场、政府和资源账本；
- 让一个默认社会能够持续运行；
- 完成守恒、生命周期和可复现性测试。

阶段产物：可通过命令行运行并导出结果的社会模拟内核。

### 阶段 2：组织、媒体和关系传播

工作内容：

- 加入家庭、社会关系、媒体、信任和观点传播；
- 加入制度支持、迁移和组织变化；
- 完善宏观指标。

阶段产物：能够出现合作、分层、极化和组织变化的完整默认社会。

### 阶段 3：实验控制台

工作内容：

- 实现浏览器控制界面；
- 实现宏观图表、关系图、个体视图和事件时间线；
- 实现暂停、单步、加速、干预和导出。

阶段产物：可交互使用的本地数字社会实验室。

### 阶段 4：四组对照实验与验收

工作内容：

- 运行默认 A、B、C、D 四组实验；
- 检查重复运行一致性；
- 分析异常和模型敏感性；
- 生成对比报告；
- 完成使用和模型说明文档。

阶段产物：第一期完整交付包。

## 11. 最终交付物

第一期最终交付以下内容：

1. **社会模拟源代码**：与 Atoll 集成的所有社会领域组件。
2. **可运行程序**：通过一条明确命令启动 Atoll、实验引擎和控制台。
3. **默认小镇场景**：100 名居民、家庭、企业、市场、政府、媒体和关系网络。
4. **四组制度配置**：高/低透明度与高/低再分配的组合。
5. **交互式 Web 控制台**：运行、暂停、单步、加速、干预、观察和对比。
6. **历史与追踪能力**：从宏观指标回到具体社会事件和个体轨迹。
7. **数据导出**：至少提供 JSON 和 CSV 格式的指标、个体状态及事件数据。
8. **自动化测试**：覆盖核心规则、守恒、幂等、时间、恢复和可复现性。
9. **实验对比报告**：呈现四组实验结果、差异、异常和可支持的结论。
10. **文档**：安装运行说明、配置参考、模型说明、指标定义和已知限制。

交付物是一个可以继续修改和扩展的研究软件项目，不是一次性的演示视频或静态报告。

## 12. 验收标准

满足以下条件时，第一期视为完成：

### 12.1 可运行

- 新环境能够按照文档启动实验；
- 默认场景无需手工修改数据库即可运行；
- 可以完成至少 10 个模拟年的运行；
- 可以暂停、继续、单步和停止。

### 12.2 可观察

- 控制台能够显示规定的核心指标；
- 可以查看居民、企业、政府和关键事件；
- 可以比较至少两个实验组；
- 可以导出实验数据。

### 12.3 可解释

- 主要行为规则均有文档；
- 指标具有明确计算公式；
- 个体的重要决策能够展示其主要输入因素；
- 宏观变化能够定位到相应时间段的社会事件。

### 12.4 可复现

- 相同版本、配置和随机种子的重复运行产生相同结果；
- 所有干预均记录时间和参数；
- 实验结果能够关联回其配置与构建版本。

### 12.5 一致和可靠

- 货币与受守恒约束的资源通过自动测试；
- 重复交易不会被重复执行；
- 暂停后逻辑社会不继续演化；
- 死亡或退出主体不再产生社会行动；
- 重启和异常不会静默改写已经发生的历史。

### 12.6 研究边界明确

- 报告明确区分模型内结果与现实社会结论；
- 已知简化、偏差来源和不支持的推论被列出；
- 第一版结果不被描述为对现实政策的直接预测。

## 13. 主要风险与处理原则

### 13.1 模型看似复杂但无法解释

处理原则：第一版优先使用显式规则、状态机和效用函数；大语言模型只在后续作为少量高级角色加入。

### 13.2 结果由参数任意决定

处理原则：公开参数、进行敏感性分析、使用多组随机种子，并避免只展示符合预期的运行结果。

### 13.3 关系网络和组织层级混淆

处理原则：channel 只表示组织边界；横向社会关系由领域图维护。

### 13.4 崩溃导致交易重复或资源失真

处理原则：所有资源转移通过领域账本、唯一交易 ID、幂等和守恒检查完成。

### 13.5 模拟规模超过 Atoll 当前承载方式

处理原则：第一期控制在 100 名居民；后续规模扩大时允许一个 actor 代表一个居民群体或仿真分区，不坚持“一人一个进程”。

### 13.6 把模拟结果误认为现实预测

处理原则：界面、导出和报告都标明实验配置、假设与适用边界。

## 14. 后续扩展方向

第一期完成后，可以按研究问题逐步增加：

- 少量 LLM 市长、媒体、企业家、活动家或思想领袖；
- 多城市、国家与跨地区迁移；
- 更完整的司法、教育和医疗系统；
- 信贷、投资和金融危机；
- 技术创新、自动化和职业替代；
- 代际流动和文化继承；
- 疾病、自然灾害和战争冲击；
- 世界快照、政策分叉和大规模参数扫描；
- 多设备并行实验。

这些扩展必须建立在第一期的可复现性、可解释性和一致性已经通过验收的基础上。

## 15. 第一项研究复核决策

第一期已经按以下默认目标实现：

> 构建一个 100 名居民、可运行 10 个模拟年的数字小镇，比较政府透明度和税收福利强度对财富分布、社会信任、观点极化、生产和危机恢复能力的影响。

下一次研究负责人复核应重点决定：是否接受当前“高再分配维持人口但积累住房与负债压力”的简化机制，还是先引入真实数据校准，再进入第二期。

### 第一期开口限制

- 媒体仍是聚合感知误差，没有逐条新闻在关系图上传播；
- 投票以连续制度支持值近似，没有离散选举制度；
- 公共服务、住房、信贷和人口生命周期是可解释的简化指数/规则，尚未现实数据校准；
- 冲击恢复天数采用人口、就业、产出和信任回到冲击前 90% 的工程口径，不代表现实社会恢复；
- 浏览器便携导出保留最多 1000 个指标点和最近 500 条审计证据；完整逐日、逐事件、逐交易数据由命令行导出；
- 第一阶段只能支持模型内机制判断，不能推出真实社会政策效果。
