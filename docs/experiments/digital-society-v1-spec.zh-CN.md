# 数字社会第一期：可执行规格

状态：第一期实现规格（模型 v1.1）  
上位计划：[digital-society-v1.zh-CN.md](digital-society-v1.zh-CN.md)

## 1. 第一条可验证路径

第一条纵向切片必须完成：

```text
固定场景 → 逻辑日推进 → 工资/税收/福利/消费 → 信任与支持率变化
        → 每日指标 → JSON/CSV 导出 → 相同种子结果一致
```

该路径先以纯确定性领域模型交付，然后通过一个 society actor 接入 Atoll。纯模型不读取墙钟、不访问网络、不调用 LLM，也不依赖 goroutine 调度顺序。

## 2. 边界

- Atoll core：身份、成员、消息、channel、持久历史、timer、恢复和权限。
- Society model：人口、经济、关系、制度、逻辑时间、随机性和指标。
- Society actor：将 Atoll 消息翻译为纯模型命令，将模型事件写回 Atoll。
- Console：只通过公开控制接口读取快照和提交命令。

第一期不得让 `runtime/` 或 `protocol/` import 社会领域代码。

## 3. 确定性规则

### 3.1 时间

- `day=0` 是场景出生后的初始快照。
- 每次 `Step` 原子地推进一个逻辑日。
- 一年固定为 365 日，一个月用于展示时按 30 日计算。
- 暂停状态下自动运行器不得调用 `Step`；手动单步仍可推进。
- 停止是终态，停止后的推进必须返回错误。

### 3.2 随机性

- 所有随机选择来自实验私有的稳定 PRNG。
- PRNG 状态属于世界状态的一部分。
- 场景种子、配置和模型版本共同决定结果。
- 禁止使用全局随机源。

### 3.3 货币

- 金额使用整数分，不使用浮点数。
- 初始货币总量在场景创建后冻结为守恒基线。
- 工资、税收、福利和消费全部通过唯一交易 ID 进入领域账本。
- 重复交易 ID 返回第一次的结果，不产生第二次转账。
- 普通交易不得透支，也不得铸造或销毁货币。

### 3.4 每日结算顺序

同一逻辑日按固定顺序执行：

1. 计算资源压力和当日企业产量。
2. 企业支付工资并向政府缴税。
3. 政府向失业居民和低于贫困线的在职居民发放安全网福利。
4. 居民在购买食物前，可由同一家庭中有余力的成员确定性补足最低食物预算。
5. 居民按固定、可解释且不偏向固定企业的轮转规则购买食物。
6. 仍有食物预算缺口时，政府可发放有明确余额来源的应急信贷；就业者按工资比例偿还。
7. 家庭资金和需求缺口更新住房安全，税率与财政充足度更新公共服务指数。
8. 未满足基本需求会降低健康与制度支持；满足需求和公共服务使健康缓慢恢复。
9. 居民与稳定选出的邻居互动并更新相互信任；媒体透明度影响感知误差。
10. 月末执行招聘、裁员和企业退出；年度边界执行简化出生，半年度边界检查需求驱动迁移；健康或年龄阈值触发死亡。
11. 计算并保存当日指标和关键事件。

### 3.5 决策可解释性

每个会改变居民就业、财富、健康、信任或制度支持的重要动作必须生成领域事件。事件至少包含：

- 稳定事件 ID；
- 逻辑日；
- 类型；
- 涉及主体；
- 输入原因；
- 数值变化；
- 关联交易 ID（若有）。

## 4. 默认场景

- 居民：100；
- 企业：10；
- 初始就业率：约 75%；
- 家庭：按 2 至 4 人确定性分组；
- 初始社会关系：家庭强连接，加少量邻里连接；
- 模拟长度：3650 日；
- 资源压力：第 3 年开始上升，第 6 年达到峰值，第 9 年回落为零；
- 默认种子：20260906。

## 5. 制度组

| 组 | 透明度 | 工资税率 | 日福利 |
|---|---:|---:|---:|
| A | 90% | 10% | 低 |
| B | 30% | 10% | 低 |
| C | 90% | 30% | 高 |
| D | 30% | 30% | 高 |

制度组只改变政策参数。初始人口属性、关系、企业属性和资源冲击序列保持一致。

## 6. 第一批领域事件

| 类型 | 含义 |
|---|---|
| `society.day.completed` | 一日结算完成 |
| `society.wage.paid` | 工资及相关税收已结算 |
| `society.benefit.paid` | 福利已结算 |
| `society.food.purchased` | 食物交易已提交 |
| `society.household.supported` | 家庭成员补足最低生活预算 |
| `society.need.unmet` | 基本需求未满足 |
| `society.employment.started` | 居民入职 |
| `society.employment.ended` | 居民失业 |
| `society.firm.closed` | 企业退出 |
| `society.policy.changed` | 政策干预生效 |
| `society.shock.changed` | 外部资源压力变化 |
| `society.credit.extended` / `society.credit.repaid` | 应急信用发放或偿还 |
| `society.citizen.born` / `society.citizen.died` | 简化生命周期事实 |
| `society.citizen.migrated` | 居民社区迁移 |

接入 Atoll 时，控制请求使用 request/response，社会事实使用 event。事件名称作为领域词汇，不加入 `protocol/message` 的系统闭集。

## 7. 指标定义

- 人口：仍存活的居民数量。
- 就业率：存活劳动年龄人口中已就业者比例。
- 总产出：当日全部企业生产的食物单位。
- Gini：存活居民非负净财富的标准 Gini 系数。
- 贫困率：可用货币低于配置贫困线的居民比例。
- 平均信任：有效社会边的信任值算术平均。
- 政府支持率：存活居民政府支持值的平均数。
- 极化指数：居民观点值相对总体中位数的平均绝对偏差，经范围归一化。
- 企业数量：未退出企业数量。
- 财政余额：政府账户余额。
- 货币总量：所有居民、企业和政府账户之和。
- 当日税收/福利：当日已提交所得税交易与福利交易的金额总和。
- 出生/死亡：当日对应生命周期事件数。
- 住房安全率：存活居民中住房安全指数至少为 60% 的比例。
- 总负债：存活居民未偿应急信贷的总和。
- 聚类系数：有效社会关系图上，度数至少为 2 的存活居民局部聚类系数均值。
- 孤立率：有效关系度数为 0 的存活居民比例。
- 公共服务：由工资税率与政府财政充足度决定并限制在 `[0,1]` 的综合指数。
- 冲击恢复天数：峰值后，人口、就业率、产出和信任同时恢复到冲击开始日 90% 水平所需天数；未恢复为 `-1`。

比例统一输出为 `[0,1]`，界面负责显示百分比。

居民快照另保留当日工资与福利收入、未偿债务和当前策略。当前策略是 `dependent`、`work-and-save`、`seek-work`、`secure-basic-needs`、`repay-debt` 或 `inactive` 之一，用于解释规则状态，不是自由文本人格推断。

## 8. 初始命令面

命令行纵向切片：

```text
atoll-society run --variant A --days 3650 --seed 20260906 --out ./run-a
atoll-society compare --days 3650 --seed 20260906 --out ./comparison
```

`run` 产生场景快照、每日指标、事件和摘要；`compare` 使用相同种子运行 A/B/C/D，并产生对比表。

## 10. 第一批验收测试

1. 相同配置和种子运行 365 日，两次最终快照和每日指标完全一致。
2. 不同制度组使用相同的初始居民、企业、关系和冲击序列。
3. 每日结算后货币总量等于初始基线。
4. 同一交易 ID 提交两次只改变一次余额。
5. 余额不足的交易被拒绝且双方余额不变。
6. 暂停后的自动运行不推进日期；单步推进恰好一天。
7. 停止后任何推进均被拒绝。
8. 同一政策干预 ID 重放不产生第二次效果。
9. 每日指标中的人口、就业、企业和财政值与世界状态一致。
10. JSON 与 CSV 导出覆盖完整日期范围并包含实验身份信息。

## 11. 阶段 0 冻结项与可调项

冻结项：层边界、逻辑时间、固定点货币、幂等交易、可复现性、事件可追踪和指标口径。

可调项：工资、价格、税率、福利、冲击曲线、行为权重、关系密度以及界面视觉设计。可调项必须通过配置改变，不能破坏冻结项。
