# CvMax 开发清单

当前进入应用层开发。CvMax 是 Atoll 的业务应用：身份、频道、消息、Agent、MCP 工具发现、权限和生命周期全部以 Atoll 为准。任何事项若必须修改这些核心能力才能成立，立即停止该事项并记录阻塞，不用旁路补齐业务。

Web 入口仅保留设计位置，本期不实现。当前交付范围是唯一 CvMax Skill、CvMax Client/CLI、Chrome 插件、招聘页面填写与核验、经验积累和有界自进化。

## D1 Chrome 插件可安装骨架（已完成）

- [x] Manifest V3、后台 Service Worker、弹窗和内容脚本组成可加载扩展。
- [x] 用户只需一次配对；服务通过插件自动打开并绑定岗位链接，不要求用户打开页面、点击插件或授权站点。
- [x] 插件只连接本机 CvMax 服务，只接受短租约、指定 tab、指定 URL 的动作。
- [x] 插件显示连接状态并提供立即停止；停止后不得自动恢复。
- [x] 招聘页打开后立即展示准备状态；执行时由服务投影当前业务大区块和临时目标引用，插件用高亮框与连接线指向正在处理的页面区域，并显示本组真实进度、已核验动作、最近确认和下一步负责人；插件不建立第二套状态机。

测试方式：解析 manifest 并核对所有入口文件；对配对地址、站点 origin、动作租约、目标绑定和进度数据边界做单元测试；在 Chrome 开发者模式加载并检查连接、字段级进度、终态和页面内停止。通过条件：安装时一次性披露招聘页面访问范围，没有硬编码凭证，越权目标与过期动作全部拒绝，进度不包含事实值且与服务 operation 一致。

## D2 Client 与唯一 Skill

- [x] `cvmax install` 通过 Atoll 公开声明/成员命令幂等安装或升级 Hosted Agent 与 stdio MCP Service；不创建第二套运行时。
- [x] 稳定 `resume-save/resume-list/resume-get/submit/status/report/answer/pause/resume/stop/skip/continue/doctor` 契约。
- [x] Client 使用用户现有 Atoll 身份和私有频道，外部宿主不冒充内部 Agent。
- [x] 对外 `submit` 只接受岗位 `links` 或 `currentPage`；精确 tab/URL 由 Hosted Agent 通过服务解析。主流程引用已保存的 `resumeId + revision`，一次性临时附件保留为兼容入口。
- [x] Skill 支持当前页、单链接和多链接三种意图，复用同一 taskId。
- [x] CLI 输出稳定的结构化状态、错误和下一步责任人。

测试方式：使用假 Atoll transport 测试请求类型、真实身份透传、幂等键、超时与未知回执；Skill frontmatter 和命令示例做结构检查。通过条件：Client 不直连浏览器、不读写 Atoll 数据库、不建立第二套身份或调度。

## D3 简历事实准备

- [x] 由宿主 AI 读取用户明确授权的本地简历，把原文件和带 `sourceRef` 的结构化投影保存为一个独立 ResumeFact。
- [x] 每份简历独立命名和版本化；任务冻结所选 revision，禁止跨简历补值，本次答案不回写简历。
- [x] 临时附件限制类型、大小、hash、有效期和当前私有作用域；保存的源文件只能位于应用私有简历路径。

测试方式：合成 PDF/文本简历覆盖确定值、缺项、冲突、过期附件和路径逃逸。通过条件：只有获准事实进入任务；只有映射到已证明必填字段的缺项进入问题流程，选填和未标必填字段允许留空；文件越界全部拒绝。

- [x] 登录、验证码和 CAPTCHA 在阻塞时转交用户；敏感字段仅在已证明必填时要求用户在页面处理，法律同意作为最终人工步骤报告但不持续等待。

## D4.1 已知页面高速路径

- [x] Agent 一次选择 exact 经验配方，Service 连续执行、统一核验，异常才返回 Agent。
- [ ] 记录从页面打开到首次可见动作、填写完成和终止状态的墙钟时间；已知页面以 P50 8 秒、P95 20 秒为目标。
- [x] Client 在服务内暂存授权请求，只向 Hosted Agent 发送 request ID；任务创建从暂存记录冻结资料，避免整份简历进入委托消息。

当前单次真实样本：任务创建到终态 27.302 秒，页面活跃 21.403 秒；Client 接收到任务创建 97.224 秒。页面路径已接近但尚未达到目标，端到端主阻塞位于 Hosted Agent 首次调度/推理。按应用层边界，不通过 Client 直驱插件或绕过内部 Agent。
- [ ] 新页面使用一次集中计划和批量动作，保留页面漂移、登录、冲突与缺项的停止边界。

测试方式：同一页面族先完成经验晋升，再以不同岗位和不同 ResumeFact 执行完整真实链路；统计 Agent turn 数、工具调用数、首次动作和完成耗时。通过条件：快速路径不读取其他简历、不绕过现有动作校验与核验，任何前置条件失败立即退出到 Agent，最终提交调用始终为零。

## D5 多岗位串行与任务控制

- [x] 冻结用户确认的岗位顺序并去重，逐个处理。
- [x] 支持暂停、继续、跳过和终止；终止优先于迟到动作。
- [x] 断线、进程重启和未知页面效果先核对，不重放。
- [x] 每次反馈最新事实、下一步负责人和明确终止条件。

测试方式：两到三个合成岗位注入断线、迟到回执、revision 冲突和重启。通过条件：同一 tab 只有一个执行所有者，未知效果不重复执行，停止后没有新页面动作。

## D6 经验积累与有界自进化

- [x] 选择 CvMax 独立远程 MySQL 作为公共经验权威库，不复用 Atoll 核心数据库。

- [x] 按 origin、归一化岗位路由和表单阶段识别页面家族；岗位 ID 和跟踪参数不影响命中。
- [x] `ready_for_review` 和 `partial` 都按字段积累最终页面仍能独立核验的成功动作；未保留、缺失、未知和仅收到执行回执的动作不进入经验。
- [x] 现有本地实现已验证字段级候选与复用算法；公共版本不得以同一实例的两个 run 直接升级，必须经服务端多实例聚合后发布。经验仅保存字段语义、控件类型、事实 ID、动作类型、页面版本和结果计数，不保存事实值或自由文本反馈。
- [x] 精确版本生成确定性的无值动作建议；轻微变体只复用仍能唯一绑定的字段，并报告新增、缺失和失配结构。
- [x] 所有经验动作仍经过普通 apply 的事实来源、已有值、敏感字段、预算、租约和页面回读门禁；不能直接驱动插件或最终提交。
- [x] 用户纠正可按 strategyId 或 fieldRef 只隔离单字段；页面回读否定已接受动作时自动隔离相关策略，传输故障不自动归为语义失败。
- [x] 用户状态与招聘页进度能够区分 cold_start、learning、exact reuse、compatible reuse 和 suspended。
- [x] 已知站点可把详情页唯一动态岗位 ID 代入已验证申请表路由；出现多个候选路由时拒绝猜测。
- [x] 同字段冲突经验全部阻断；精确候选版本不可用时可回退到仍能唯一绑定的兼容经验版本。
- [x] 在两个不同字节岗位的空白申请表上形成独立成功 run，并在后续正式链路中命中 exact reusable 页面版本；网站原生解析优先，经验建议用于后续核对与补填，不越过原生解析策略直接竞速执行。

测试方式：同页面不同岗位 ID、动态 DOM ID、轻微变体、结构漂移、partial、字段纠正、语义执行失败和传输故障夹具；最后做三个真实岗位的插件复用验收。通过条件：未经核验的经验不可复用，兼容漂移只执行稳定子集，失败字段单独隔离，经验存储不包含简历原值、自由文本反馈或用户身份信息。
