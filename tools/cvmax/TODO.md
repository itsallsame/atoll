# CvMax 极简 Recipe 状态机实施清单

2026-09-13。本文是当前唯一实施与验收清单。所有修改仅限 `tools/cvmax/`；若实现必须改变 Atoll 核心，立即停止并报告阻塞。历史完成记录不再作为当前状态，也不保留已经失效的双路径代码。

## 方案摘要

Recipe 是唯一业务状态机。Service 持久化当前 Recipe transition cursor，但不另建 Application workflow。Recipe 不建立全局“标准页面”：每一步只包含粗粒度业务里程碑、当前动作目标的局部精确守卫、动作和局部后置条件；Page Model 只解释字段与 ResumeFact 的关系，不参与流程身份。Chrome 扩展只提供观察、动作、回执和进度原语；它不判断业务流程。每条 Recipe transition 按以下顺序运行：

`locked → dispatching → settling → matched`

异常出口只有 `timeout`、`gate`、`unknown`、`cancelled`。transition 在动作创建时即取得页面解释权，直到进入上述终态才释放；加载、刷新、SPA 重渲染和文档 epoch 变化都是 transition 内部观测，不是新的 Recipe 状态，也不能触发 Agent。浏览器 `accepted` 回执只证明动作已被接收，后置业务状态精确匹配才证明 transition 完成。

命中目标状态后立即选择并执行下一条边，不增加固定静默等待。轮询只是没有页面事件时的有界兜底，因此正常快路径不会为弱网保护支付固定延迟。服务重启从持久化游标继续等待，已经取得回执的动作不得重放。只有真实缺少 Recipe 分支、后置条件超时、登录、验证码或浏览器安全门槛才交给 Agent/用户。
