设计基线 b447c91a，业务扩展仅在应用层。细化方案见 [SYSTEM-DESIGN.md](SYSTEM-DESIGN.md)。以下区分代码依据、历史实测、当前实现与未来入口。

## 1. 不变量与修改范围

先满足 Atoll 身份、频道成员权限、消息、生命周期与扩展原则，再实现业务。唯一修改目录 tools/cvmax/；不能修改 protocol/runtime/lib/platform/registry/drivers/cmd/archtest、根依赖、既有 Web UI、核心数据或权限规则。配置现有类与频道通过公开管理接口进行，不等同于新增内置类。

不要为了形式上的“文件都在 tools 下”而另建通用调度器、身份库或消息总线。应用可管理招聘领域状态、动作租约和有限预算，不可取代核心 Actor 管理。

## 3. 默认装配

首版以用户私有 CvMax 频道/服务实例装配：既有人类成员、一个现有类型的业务 Agent、一个 CvMax MCP 工具，绑定获准设备。当前 Client 使用既有 principal；未来入口也必须认证为同一 principal。应用私有存储按服务实例隔离，禁止用调用参数切换其他用户存储。

外部 Skill 经 CLI 使用现有频道公开入口委托内部 Agent。内部 Agent 经标准工具桥调用同一 MCP 应用工具。状态查询及暂停/停止由公开业务控制工具处理，不要求经过模型推理。未来 Web 必须沿同一入口和状态接入。

现有 svcactor/peer 是候选服务发布机制，不能把“业务服务”一词自动等同于必须再加一层 svcactor。默认同频道装配先验证；跨频道映射只有产品隔离需求与现有契约验证支持时启用。

## 4. 三种身份不可混用

- 外部 AI 是用户授权的客户端；CLI 使用显式配置的 Atoll 身份，请求发送者如实为 human。不能宣称它成为系统内 Agent。
- 托管 CvMax Agent 使用原有工具桥，调用以其真实身份进入账本；不得运行带人类凭证的 CLI 替换身份。
- 应用 MCP 参数不是可信身份通道。actorId/origin/taskOwner 等应用字段仅作业务关联，不可据此授权。权限以原有系统入口为准。

单一业务决策主体是应用职责约束，不等于新安全角色。若要阻止某类有频道资格的成员访问底层工具，必须验证现有频道/服务曝光是否提供所需隔离，不能靠隐藏 CLI 命令冒充系统权限。

## 5. 状态与执行所有权

| 事实 | 唯一权威 |
|---|---|
| 认证 principal、成员、系统请求响应、Actor 生命周期和系统调度 | Atoll |
| taskId、申请范围、资料版本、问题、业务状态、预算、动作证据与经验版本 | CvMax 应用工具持久存储 |
| 页面现状和站点接受结果 | 可观察网页证据 |
| 业务下一步决策 | 内部 CvMax Agent，计划仍须应用校验 |
| 对话措辞、显示偏好、临时资料整理 | 当前入口，不得覆盖权威状态 |

系统消息终态不等于业务任务完成；模型轮次结束不删除 Task。客户端断线不撤回已接受委托，任务继续所需的重入/唤醒必须沿系统现有机制且取得证据。

领域控制先落库并阻断旧 epoch，再协调 Agent。应用工具调用短时返回，不在 stdio 请求中等待用户或反向等待 Agent。复杂控制若必须经过正在阻塞的模型才可停止，则该设计不能通过。

同一申请的并发计划、回答、暂停和停止以条件写与应用事务归并。界面只读缓存不派发动作；跨入口切换不会创建第二个执行器。断线与崩溃后 unknown 先观察，停止优先，不自动重放。

## 6. 文件、插件和能力边界

固定本地拓扑已验证；文件引用需授权、可达性、版本与 hash，不能传任意路径即读。当前 Client 将本次附件暂存为私有、有期限引用，不把大附件拼入消息。跨设备和未来 Web 文件仍须走现有文件数据面并单独验收。

插件仅接受配对应用工具发来的目标绑定动作，并检查有效 run/epoch/document/租约；网页文字是不可信资料，不能让其启动任务或改边界。插件断连立即阻止新动作，恢复只补报并核对，不能自行续跑。

暂停/停止成功必须有领域闸门和浏览器侧证据；agent.interrupt 只控制 Agent，不自动证明网页副作用结束。未能确认的在途动作如实报告 unknown。

## 7. 发现异常的修正分类

早期实验中的空 words 与指定查询失败已经定位并修复；这些实验不再维护为独立产品流程。

外部固定 CLI 客户端知道业务契约是合理设计，不等于旁路；不能仅凭 describe 空表判定所有客户端不合法。新版内部 Agent 标准工具指导包含发现步骤，svcactor 卡片也使用 describe，因此应在 A1 中复现其实际影响并核对可用的既有契约。

保留有效回归断言，不删除断言制造通过；不继续扩大核心修改、不编造返回 schema，不让外部模型代替内部 Agent。若必要路径只能通过触碰核心完成，则停止该路径并报告。

## 8. 停止条件与待证项

必须停止受影响实施的情况：需修改核心类型/路由/权限/注册/调度；需直接读写核心 DB 或伪造身份；需自建绕过 Atoll 的启动/恢复路径；无法实现可靠停止、身份隔离或结果真实性；必须改现有核心 Web 才能完成其必要入口。

A1 至 D 的当前应用范围已经证实 Client 委托、内部 Agent 真实工具桥、附件、完整页面填写、停止、重启恢复和经验复用。生产多站点覆盖、跨设备文件、未来 Web 同身份接续和独立发布仍待后续工程。具体边界见 SYSTEM-DESIGN 第 9 节。

阻塞报告须包含用户需求、系统原则、实际公开调用、最小复现、失败证据、核心边界、仍在原设计内的调整及限制、停止范围。无法做到账实一致时不改业务承诺，也不把缩小入口范围当完成。

A2 实施确认 Client 使用现有 principal 与频道、答案持久化和停止闸门等关键约束。相关回归作为普通开发测试维护，不建立独立验证产品流程。
