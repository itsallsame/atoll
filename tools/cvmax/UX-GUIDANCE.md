# CvMax 状态与渐进引导 v2.0

本规范适用于当前外部 AI 入口、插件及未来 Atoll Web。服务结构见 [SYSTEM-DESIGN.md](SYSTEM-DESIGN.md)。

CvMax 采用 AI-first 交互：当前业务输入发生在外部 AI 对话中，用户可用自然语言引用本地文件、岗位和答案。未来 Web 只展示信息、状态与证据并接入对话；不得把任务创建、资料补充、安装诊断重新设计成表单、设置页或工作台。插件只保留现场状态与紧急停止。

招聘页打开后立即显示“正在建立任务并识别页面大区块”。实际操作超过瞬时反馈时，插件展示完整用户业务流程：打开申请页、进入简历流程、选择填写方式、网站上传并解析简历、填写或纠正简历事实、核验简历事实、用户处理剩余内容；当前步骤高亮，已完成步骤打勾，确定不走的分支标为已跳过，登录或验证码停在实际受阻步骤。该流程由 Service 投影，插件不得据此另建业务状态机。插件同时按业务大区块展示当前位置，并用页面高亮和连接线关联进度卡；不要求用户从细粒度字段日志推断系统正在做什么。进入终态、停止或目标离开视口时撤销或隐藏页面指示，不修改招聘站 DOM 状态。

## 1. 四项交互原则

1. 明确对象、范围、完成边界和终止条件。
2. 最近确认事实 + 当前是否执行 + 下一步负责人。
3. 最多三个简短阶段；只展开当前一步，完成后再展开下一步。
4. 已授权且可自主完成的诊断、定位、填写和核验直接做；不反复确认同一范围。

所有入口必须表达同一服务事实；模型只能解释回执，不能把消息接收说成任务完成、把过期记录说成正在执行。

## 2. 结构化状态契约

服务响应拟包含 schemaVersion、taskId、applicationId、runId、operationId（按需）、revision、state、phase、lastConfirmedAt、freshness、blockingReasons、questionId、nextActionOwner、nextAction、terminal、retryable、originRequestId。

nextActionOwner 为 service/user/none；等待外部站点时明确当前条件与预算。展示一次只给一个当前主动作；其他问题保留在记录，不全部倾倒。

| 状态 | 告知事实 | 下一步 |
|---|---|---|
| 消息已收到，任务尚未记录 | 当前只确认系统接收，尚未确认业务接受 | 服务核查；未知不得重复创建 |
| queued/needs_attention | 已保存委托，但当前未执行；说明等待或故障原因 | 有界恢复或当前用户动作 |
| running | 正在观察/填写/核验指定申请 | 用户暂时无需操作；可暂停/停止 |
| waiting_user | 登录、验证码/CAPTCHA、阻断式法律同意弹窗或已验证的页面前置必填项阻止进入简历区域，已保留什么 | 在招聘站完成当前一步 |
| paused | 用户已暂停，最后确认成果 | 明确继续才能恢复 |
| needs_reconcile | 外部动作结果不确定 | 先只读核对，不盲重试 |
| ready_for_review | 整份申请已到最终边界，必填解决且无未知动作 | 用户原站检查提交 |
| partial/failed | 可确认成果与具体未解决项 | 明确人工出口或结束 |
| cancelled/停止中 | 已封锁新动作，尚需区分在途结果 | 有界只读核对；旧 run 不复活 |
| Task finished | 本轮自动执行结束及各申请结果分布 | 不暗示每项成功或网站已提交 |

停止受理、派发已阻断、浏览器效果已确认分别表达；无法取得后两者证据时不能只显示笼统“已安全停止”。

## 3. 渐进引导示例

登录概览：“定位页面 → 你来登录 → 核验继续”。先自主定位，只要求用户当前在招聘站登录；密码和验证码留在网站。用户说完成后服务核验账号/岗位/表单，不直接信任一条回复。

连接故障概览：“检查连接 → 恢复设备 → 核验继续”。先由服务诊断；需要用户时只展示具体设备当前一步。不指导改核心或绕过权限，不把三段写成三篇教程。

只有登录、验证码/CAPTCHA、当前实际遮挡并阻止进入简历流程的法律同意弹窗，以及确实阻挡进入简历区域的页面前置必填项创建等待问题。登录账号和简历联系方式允许不同，不比较、不询问。最终提交阶段的法律同意不逐项询问，在简历内容填写并核验后统一列为人工处理项。没有观察到法律同意的公司不进入该分支。用户在另一入口已经完成登录或前置操作，当前入口先刷新，禁止再次询问。

## 4. 当前入口与未来多入口冲突

主要反馈偏好跟随最近交互入口；其他入口可读同一状态。无需额外通知管理中心，不保证第三方桌面离线推送。

问题以 questionId/revision 关联：已解决显示解决事实；同答案重复无副作用；不同答案显示版本变化并读取当前值。不能用最后到达的聊天文字覆盖已完成事务。

从另一入口接续先说“上次停在 X，现在先核验 Y”，随后读取服务和网页；不重新讲全部流程，不凭对话记忆重复执行。

用户关闭入口：业务授权不自动撤销。依赖仍有效时内部服务按范围继续，需用户时持久等待；服务断开则展示最后确认时间，不假装在线执行。

## 5. 经验反馈与边界

经验只显示已记录候选、验证通过、已隔离、已禁用。一次成功不是已学会；禁用错误经验不等于网页已修复。纠正回执说明作用范围和当前页面是否仍需修改。

用户修改值优先；旧计划失效，重新核对来源和网页。停止后的登录、刷新、晚到回执、换入口或重启均不能解除闸门。

一期不承诺原网站草稿保存、自动登录、最终投递、全站适配、关闭外部宿主后的通知送达或全链路历史擦除。

## 6. 必需验证

当前外部 AI 与插件必须显示对象、事实、时间和下一步；CLI 的停止、问题解决、答案冲突、失联状态和插件焦点引导均需实测。未来 Web 接入时再验证跨入口同步，旧本地原型不能替代。
