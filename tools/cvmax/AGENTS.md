# CvMax 应用开发约束（v2）

先读 README.md、SYSTEM-DESIGN.md、PRODUCT-DESIGN.md、ARCHITECTURE-FIT.md；旅程与交互见 USER-JOURNEYS.md、UX-GUIDANCE.md。history/、reviews/ 和旧 prototype 只提供带版本的历史材料，不据其恢复被替换职责。

- Atoll 是前提，CvMax 是在其原有设计内的业务落地。业务完整和架构符合必须同时验收。
- 仅修改 tools/cvmax/，沿用 codex/job-application-autofill；不改核心代码/设计/依赖/注册/既有 Web/archtest 或核心数据库。不得旁路身份、权限、消息与生命周期。
- 2026-09-05 用户明确授权例外：“按照你定位的原因修复吧。”允许修复已定位的 MCP 动态定义发布/刷新恢复缺陷及相关定义读取错误处理，并增加回归测试；不扩大到其他核心变更或修改上述产品边界。
- 一期当前只实现外部 AI 的 Skill 接入；Atoll Web 保留入口设计但不开发。内部托管业务 Agent 统一决策；外部宿主只做资料准备、委托、查询、回答与展示，不维持第二套字段执行循环。
- Client 使用 Atoll 既有身份和私有频道。CLI 是公开契约客户端，不能直连插件启动或恢复；内部 Agent 用原有工具桥，不能借人类凭证改变调用身份。
- 应用工具拥有领域持久状态、动作校验和执行预算；不另建通用调度器。插件可立即阻断，但无自主恢复/启动权。停止模型响应不等于停止页面动作。
- 简历事实按每份简历隔离并保留在用户私有侧；公共经验网络与有界自进化为一期必需。公共经验的权威库是 CvMax 应用自有 MySQL，不进入 Atoll 核心数据库，只保存无事实值的页面结构、策略发布和匿名核验反馈。商业账号、推荐数据、支付在二期。不得把 Web 入口原型称为本期已实现能力。
- 只填写核验，不最终提交；明确最新事实、下一步负责人、范围和终止出口。最多三个短阶段，只展开当前一步，已授权可自主做的自行做。
- 若必要能力需要触碰核心或旁路系统才能实现，停止受影响实施，给实际调用/最小复现/证据。无需为已授权应用内调整重复请求许可。
- 保留历史发现异常，固定 CLI 接口映射不等于旁路；内部 Agent 必须遵循其现有工具契约。不得删旧失败断言制造通过，新验收单独记录。
- 代码存在、旧 UI 模拟和十角色推演均不算新版真实链路证据。A1/A2/A3 先实证，再扩展完整申请、经验、原型和角色复验。
