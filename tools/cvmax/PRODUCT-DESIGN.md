# CvMax 产品设计 v2.0

当前有效设计，取代 v1 外部 Codex 主导方案。应用层主流程已经实现并完成真实不提交验收；Web 入口和生产发布仍不属于当前完成范围。系统细节见 [SYSTEM-DESIGN.md](SYSTEM-DESIGN.md)，核心边界见 [ARCHITECTURE-FIT.md](ARCHITECTURE-FIT.md)。

## 1. 定位和固定原则

先有 Atoll，再以招聘申请填写验证其业务落地。CvMax 是 Atoll 上的业务服务；当前入口是外部 AI，未来可接 Atoll Web；Skill、CLI、应用工具与浏览器插件是组成部分。

- 仅在 codex/job-application-autofill 分支的 tools/cvmax/ 开发，不改核心设计、逻辑、代码或既有核心 UI。必要契约不支持时停止受影响实施。
- 一期实现用户已有 AI 桌面的 Skill 接入。Atoll Web 只保留未来入口位置；任何入口都必须复用一个内部业务决策主体、一份用户私有任务状态和一套 CvMax 公共领域经验。
- AI-first：用户通过对话表达目标、引用本地文件和回答当前问题；不在 CvMax 页面重复填写简历、岗位或配置表单。独立远端 Web 只展示说明、状态、证据和结果。
- 外部宿主接待用户、准备获准资料、委托与展示；内部业务 Agent 决定页面分析、执行及异常处理。避免双方重复维护计划。
- 保留当前页面、单链接、多链接三个场景。首版串行；已明确委托清单后不逐岗位重新询问启动许可。
- 只填写和核验，到最终复核前结束，最终提交由用户在招聘站完成。
- 新页面能分析的分析、能安全填写的填写；事实缺失与能力不支持分别告知，不猜资格、薪资或意愿。
- 经验积累与有界自进化是一期必需能力，不能为了演示省掉。
- 公共经验服务属于一期应用基础设施：面向所有用户发布去事实值的页面配方；简历、任务答案和附件仍只属于用户私有侧。
- 状态明确对象、最近事实、下一步负责人和终止条件。最多三个短阶段，仅展开当前一步；已授权且可独立完成的操作直接做。
- 一期保存本机简历事实，但不建立跨简历的“候选人总档案”：一份简历是一个独立、可命名、可版本化的事实单元，其结构化投影只属于该简历。商业账号、跨设备同步、岗位推荐、支付和后台仍在二期。

## 2. 产品组成和最小界面

| 用户所在位置 | 最小使用体验 |
|---|---|
| Atoll Web（未来） | 只读信息展示及现有频道对话接入；当前不作为已实现入口，不新增专用表单或工作台 |
| 外部 AI 桌面 | 配置一次服务连接 → 安装适配该宿主的 Skill → 用自然语言委托、查询和回答；无需逐条手输 CLI |
| 招聘页插件 | 页面打开后立即显示准备状态；执行时按“基本信息、教育经历、实习经历、项目经历”等大区块展示当前位置，以区块高亮和连接线指向正在处理的区域，同时显示本组序号、已核验动作、下一步负责人和立即停止；没有独立任务规划或资料中心 |

外部宿主不必与内部模型引擎相同；一期先验证一组可用组合，再按实测支持表扩展。Skill 格式、命令执行和本地文件能力按宿主确认，不宣称“一份 Skill 安装到任意桌面都可用”。内部引擎按 Atoll 既有配置和凭证运行，不自动继承外部 AI 桌面的登录。

未来 Web 只复用 Atoll 既有对话与附件能力；状态卡只读展示事实和快捷回复，不建立 CvMax 专用录入页或操作后台。当前不实现 Web，不改既有 Web 核心，也不把另建网页算作系统入口。

## 3. 完整核心流程

1. 接受委托。用户在任一入口指定岗位范围和本次资料，明确填写不提交。歧义只澄清当前必要对象。打开网页本身不构成新授权。
2. 核查条件。确认真实身份、服务频道、内部 Agent、工具、浏览器与资料可达性。指出当前失败环节，不能偷换成另一条执行链。
3. 准备资料。首次使用某份简历时，外部宿主读取用户明确授权的本地文件，形成一个 `ResumeFact`：原文件、该文件专属的结构化投影、名称和版本。相同字段出现在其他简历中也不合并；未知和冲突保留在该简历边界内。
4. 持久接受任务。用户指定一份简历后，内部 Agent 调应用工具固定 taskId、申请清单、`resumeId + revision`、本次岗位答案和预算。服务冻结该版本的完整快照；之后更新简历不改变已创建任务。Atoll 消息接收不等于任务已记录；先取得业务回执再称已建立。
5. 观察和策略选择。内部 Agent 检索验证经验并识别页面能力。若存在高置信度的网站原生简历解析，先在无未授权旧值的前提下使用。若网站要求先上传才显示解析入口，则先单独上传、重新观察一次，随后直接触发已上传简历的解析；仍不存在则进入 CvMax 自主填写。
6. 解析后核对或自主填写。原生解析只有在表单产生可读变化后才算生效；CvMax 将结果与带来源事实对比，纠正解析器错值并补齐遗漏。原生解析不可用、无效或超时时，同一任务转入 CvMax 自主填写。
7. 必要人工交接。只有已证明为必填、且缺失会阻止自动流程继续的事实才形成服务侧 Question；登录/验证码在招聘站完成。选填和未标必填字段允许留空，法律同意作为最终人工步骤列入结果而不进入等待。当前入口回答保存的问题，未来入口也必须复用同一问题；解决后核验再继续，用户暂停/停止优先。
8. 交付申请结果。整份表单已到最终复核边界、必填解决且无未知操作，才是 ready_for_review。存在最终人工步骤时可结束为 partial；结果只列真正的必填阻塞、能力不支持、未知效果和人工步骤，选填空白不作为未完成。
9. 记录经验。内部 Agent 提候选，应用工具验证、持久化、隔离和回退。经验保存失败单独报告，不掩盖填写结果，也不算一期经验验收通过。
10. 下一岗位或结束。沿冻结授权清单处理。人工阻塞默认暂停委托，用户可跳过；结束时逐项计数，不能把批次 finished 表达为全部成功。

## 4. 领域模型和边界

ResumeFact → ResumeVersion → SourceDocument + StructuredProjection；ApplicationTask → ResumeFactSnapshot + TaskAnswers → Application → Run → Operation，另有 Question、Evidence、Experience。所有业务状态由应用工具持久写入；入口缓存与模型对话不是权威。

字段结果区分 verified、preserved、required_missing、manual_final_step、ambiguous_question、option_unmatched、unsupported_control、validation_failed、unknown_effect、skipped_optional、unmarked_blank。应用级完成、模型轮次完成、页面接受、网站最终投递是四个不同事实。

答案默认仅本申请；跨本批使用需要明确范围，修改简历必须形成新 revision。任务只能使用所选简历版本及本次答案，不能从同一用户的其他简历补值。事实快照版本变更不得静默覆盖已填写结果；经验不保存跨用户真实答案。

重复请求按 clientRequestId 去重；跨入口更新带 expectedRevision/questionId；页面动作带 runEpoch/documentEpoch 与租约。停止不因晚到答案、刷新或重新登录而解除；旧 run 重新开始必须创建新 run 并继承申请级预算。

默认应用预算草案：字段 2 个策略、每页 3 次重规划、申请累计 10 分钟活跃执行；人工等待不计入。未知动作最多 30 秒只读核对，之后交付未知结果而不是自动重试。具体数值须实测。

## 5. 经验与自进化

证据 → 同类经验检索 → 内部 Agent 生成有限动作候选 → schema/前后条件检查 → 测试页和真实受约束验证 → 升级可复用 → 漂移隔离/回退。

升级初始门槛草案：fixture 通过且两次不同 run 成功，无未解决冲突；独立变体用于评测而非全部训练。单次成功只是候选。语义错误或用户纠正立即隔离；网络故障不自动归为语义失败。

只组合已发布 setText/selectOption/searchSelect/uploadAttachment/inspectValidation/nextKnownStep 等动作。不执行任意生成 JS，不修改核心、权限、测试或 Skill 强制边界。新动作开发仍需应用版本交付。

性能采用双路径：已验证页面由 Agent 选择经验版本，应用服务批量执行已验证配方并统一核验；新页面由 Agent 集中分析一次，服务执行完整计划，只有结构漂移、冲突或缺项才回到 Agent。保存的 ResumeFact 使两条路径都无需重复读取和结构化同一简历。页面打开后 300ms 内显示工作状态；已知页面目标 P50 小于 8 秒、P95 小于 20 秒，新页面目标 P50 小于 30 秒、P95 小于 60 秒。指标是发布门槛，不能以页面活跃预算代替端到端墙钟时间。

## 6. 一期、二期和交付

一期包含外部 AI + Skill 入口及完整本地执行、资料交付、故障处理和经验闭环。同机 Atoll、文件和浏览器已经验证；关闭入口不等于关停服务，但能否继续取决于内部执行与依赖是否仍有效，不能承诺无条件后台运行。

二期：独立商业账户与 Atoll 身份映射、岗位数据与推荐、支付、管理后台；云端/跨设备部署也需另行验证。推荐是新的选岗来源，仍复用同一委托服务。

验收顺序：A1 内部 Agent 一字段 → A2 Skill/Client 正式入口与任务控制 → A3 权限/文件/生命周期故障 → B 完整申请 → C 经验闭环 → D 安装、宿主支持与真实链路复验。未来 Web 接入单独验收，不能阻塞或冒充当前入口。具体证据见 SYSTEM-DESIGN 第 9 节。

旧原型、旧十角色报告和旧直接工具调用夹具都保留作历史材料。当前未交付 v2 产品、未验证其宿主支持或上线能力。
