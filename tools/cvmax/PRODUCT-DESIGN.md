# CvMax 产品设计 v2.0

当前有效设计，取代 v1 外部 Codex 主导方案。应用层主流程已经实现并完成真实不提交验收；Web 入口和生产发布仍不属于当前完成范围。系统细节见 [SYSTEM-DESIGN.md](SYSTEM-DESIGN.md)，核心边界见 [ARCHITECTURE-FIT.md](ARCHITECTURE-FIT.md)。

## 1. 定位和固定原则

先有 Atoll，再以招聘申请填写验证其业务落地。CvMax 是 Atoll 上的业务服务；当前入口是外部 AI，未来可接 Atoll Web；Skill、CLI、应用工具与浏览器插件是组成部分。

- 仅在 codex/job-application-autofill 分支的 tools/cvmax/ 开发，不改核心设计、逻辑、代码或既有核心 UI。必要契约不支持时停止受影响实施。
- 一期实现用户已有 AI 桌面的 Skill 接入。Atoll Web 只保留未来入口位置；任何入口都必须复用一个内部业务决策主体、一份用户私有任务状态和一套 CvMax 公共领域经验。
- AI-first：用户通过对话表达目标、引用本地文件和回答当前问题；不在 CvMax 页面重复填写简历、岗位或配置表单。独立远端 Web 只展示说明、状态、证据和结果。
- 外部宿主接待用户、准备获准资料、委托与展示；内部业务 Agent 决定页面分析、执行及异常处理。避免双方重复维护计划。
- 保留当前页面、单链接、多链接三个场景。首版串行；已明确委托清单后不逐岗位重新询问启动许可。
- 只填写和核验，到最终复核前结束，最终提交由用户在招聘站完成。
- 新页面能分析的分析、能安全填写的填写；事实缺失与能力不支持分别告知，不猜资格、薪资或意愿。
- 经验积累与有界自进化是一期必需能力，不能为了演示省掉。
- 公共经验服务属于一期应用基础设施：面向所有用户发布去事实值的页面配方；简历、任务答案和附件仍只属于用户私有侧。
- 状态明确对象、最近事实、下一步负责人和终止条件。最多三个短阶段，仅展开当前一步；已授权且可独立完成的操作直接做。
- 一期保存本机用户补充资料与简历库：补充资料保存简历通常不包含、但网站可能要求的稳定个人事实；每份简历仍是独立、可命名、可版本化的事实单元，不能互相补值。创建任务时按“补充资料 → 本次所选简历 → 本次任务答案”的优先级冻结快照。商业账号、跨设备同步、岗位推荐、支付和后台仍在二期。

## 2. 产品组成和最小界面

| 用户所在位置 | 最小使用体验 |
|---|---|
| Atoll Web（未来） | 只读信息展示及现有频道对话接入；当前不作为已实现入口，不新增专用表单或工作台 |
| 外部 AI 桌面 | 配置一次服务连接 → 安装适配该宿主的 Skill → 用自然语言委托、查询和回答；无需逐条手输 CLI |
| 招聘页插件 | 页面打开后立即显示准备状态；执行时按“基本信息、教育经历、实习经历、项目经历”等大区块展示当前位置，以区块高亮和连接线指向正在处理的区域，同时显示本组序号、已核验动作、下一步负责人和立即停止；没有独立任务规划或资料中心 |

外部宿主不必与内部模型引擎相同；一期先验证一组可用组合，再按实测支持表扩展。Skill 格式、命令执行和本地文件能力按宿主确认，不宣称“一份 Skill 安装到任意桌面都可用”。内部引擎按 Atoll 既有配置和凭证运行，不自动继承外部 AI 桌面的登录。

未来 Web 只复用 Atoll 既有对话与附件能力；状态卡只读展示事实和快捷回复，不建立 CvMax 专用录入页或操作后台。当前不实现 Web，不改既有 Web 核心，也不把另建网页算作系统入口。

## 3. 完整核心流程

1. 接受委托。用户在任一入口指定岗位范围和本次资料，明确填写不提交。歧义只澄清当前必要对象。用户提交的链接清单或明确选择的当前页，构成对应 Application 的页面授权；仅仅发现浏览器中存在某个网页不构成授权。
2. 核查条件。确认真实身份、服务频道、内部 Agent、工具、浏览器与资料可达性。指出当前失败环节，不能偷换成另一条执行链。
3. 准备资料。首次使用某份简历时，外部宿主读取用户明确授权的本地文件，形成一个 `ResumeFact`：原文件、该文件专属的结构化投影、名称和版本。相同字段出现在其他简历中也不合并；未知和冲突保留在该简历边界内。
4. 持久接受任务。用户指定一份简历后，内部 Agent 调应用工具固定 taskId、申请清单、`resumeId + revision`、本次岗位答案和预算。服务冻结该版本的完整快照；之后更新简历不改变已创建任务。Atoll 消息接收不等于任务已记录；先取得业务回执再称已建立。
5. 观察和 Recipe 选择。Service 先用招聘系统身份、粗粒度业务里程碑和当前动作的局部精确守卫查询 Recipe 有序程序。唯一转换直接执行；终态直接结束；缺少转换或转换冲突时，内部 Agent 只学习当前缺口。选择了 ResumeFact 时先发现并使用网站原生简历流程；网站要求先上传或覆盖旧简历时，沿同一 Recipe 连续完成上传、确认和解析观察。用户选中的新简历覆盖站内旧简历。
6. 解析后核对或自主填写。原生解析只有在表单产生稳定可读变化或网站给出明确成功证据后才算生效；姓名、联系方式、教育等关键事实只用于证明解析发生，不能作为任务完成条件。Service 继续按 ApplicationPlan 遍历项目、校园等区块，必要时动态添加重复记录并填写剩余事实；原生解析能力确定不存在或有界期限内稳定无效果时，同一任务转入自主填写。
7. 必要人工交接。只有登录、验证码/CAPTCHA、实际遮挡并阻止进入简历流程的法律同意弹窗，以及确实阻挡进入简历区域的页面必填前置项可以形成服务侧 Question。登录账号与简历联系方式相互独立，不做身份一致性检查。最终提交阶段的法律同意不进入持续等待，只汇总为最终人工清单。未观察到的门槛不参与当前流程。用户暂停/停止始终优先。
8. 交付申请结果。冻结 ApplicationPlan 中每个附件和事实都必须有页面回读、明确无字段、不支持或不适用的证据，责任账本无 pending 才达到 CvMax 完成边界。Recipe 终态和当前页面字段集合都不能缩小该计划。整份表单也满足站点要求时为 ready_for_review；仍有页面专属内容时结束为 partial，并明确告诉用户手动处理后自行决定是否提交。
9. 学习 Recipe。每个动作只有在后置页面状态经回读确认后，才作为当前节点的一条转换立即写入整张 Recipe 图；完成边界写成终态。公共 Registry 接收不含事实值的完整图，由多安装核验后签名发布。保存失败单独报告，不掩盖填写结果，也不算一期学习验收通过。

10. 下一岗位或结束。沿冻结授权清单处理。人工阻塞默认暂停委托，用户可跳过；结束时逐项计数，不能把批次 finished 表达为全部成功。

页面级入口只支持两种。第一种是岗位详情页：CvMax 识别唯一安全的“申请/投递”入口并自动触发，再根据回读结果绑定同一 Tab、新 Tab 或当前页面内出现的表单区域。第二种是最终填写页：CvMax 跳过申请入口动作，立即进入简历策略和字段填写。两种入口一旦获得可观察的申请表，就进入完全相同的填写、核验、终止和经验流程。

岗位列表、搜索结果、公司首页和其他导航页面不属于页面级入口；系统不从这些页面自行选择岗位。详情页触发后若只出现登录或简历前置页面，则按现有人工交接状态暂停；若没有产生新 Tab、URL 变化或可观察表单，也不猜测成功，按入口无效果处理。最终投递始终不执行。

## 4. 领域模型和边界

UserProfile → SupplementalFactRevision；ResumeFact → ResumeVersion → SourceDocument + StructuredProjection；ApplicationTask → ApplicationFactSnapshot（补充资料 revision + 单一 ResumeVersion + TaskAnswers）→ ApplicationPlan + ObligationLedger → Application → Run → Operation；学习侧为 RecruitmentSystem → Recipe → StateNode → VerifiedTransition → SignedRelease。所有业务状态由应用工具持久写入；签名发布缓存、可重建页面投影与模型对话不是权威。

字段结果区分 verified、preserved、required_missing、manual_final_step、ambiguous_question、option_unmatched、unsupported_control、validation_failed、unknown_effect、skipped_optional、unmarked_blank。应用级完成、模型轮次完成、页面接受、网站最终投递是四个不同事实。

答案默认仅本申请；跨本批使用需要明确范围，修改简历必须形成新 revision。任务只能使用所选简历版本及本次答案，不能从同一用户的其他简历补值。事实快照版本变更不得静默覆盖已填写结果；经验不保存跨用户真实答案。

重复请求按 clientRequestId 去重；跨入口更新带 expectedRevision/questionId；页面动作带 runEpoch/documentEpoch 与租约。停止不因晚到答案、刷新或重新登录而解除；旧 run 重新开始必须创建新 run 并继承申请级预算。

默认应用预算草案：字段 2 个策略、每页 3 次重规划、申请累计 10 分钟活跃执行；人工等待不计入。未知动作最多 30 秒只读核对，之后交付未知结果而不是自动重试。具体数值须实测。

## 5. Recipe 与自进化

当前快照 → 粗粒度业务里程碑与局部动作守卫 → 唯一已核验步骤程序化执行 → 局部后置条件回读。没有步骤时，内部 Agent 生成一个有限动作候选；应用工具完成 schema、权限和前后条件检查，执行并回读成功后立刻把该步骤加入 Recipe。无关网站字段和语义解释修正不使已有步骤失效；动作目标缺失、不唯一或局部守卫冲突时才重新学习。

本机一次核验成功即可供同一安装的下一次任务复用；公共发布仍要求多个独立 installation 对整张图的同一转换给出一致证据。语义错误或用户纠正立即暂停对应转换；网络故障不自动归为语义失败。

只组合已发布 setText/selectOption/searchSelect/uploadAttachment/inspectValidation/nextKnownStep 等动作。不执行任意生成 JS，不修改核心、权限、测试或 Skill 强制边界。新动作开发仍需应用版本交付。

性能采用一张图的两种状态：已知节点由 Service 沿唯一转换连续执行，不启动 Agent；未知节点由 Agent 只补当前缺失转换，随后回到同一张图。保存的 ResumeFact 使两种状态都无需重复读取和结构化同一简历。页面打开后 300ms 内显示工作状态；已知页面目标 P50 小于 8 秒、P95 小于 20 秒，新页面目标 P50 小于 30 秒、P95 小于 60 秒。指标是发布门槛，不能以页面活跃预算代替端到端墙钟时间。

## 6. 一期、二期和交付

一期包含外部 AI + Skill 入口及完整本地执行、资料交付、故障处理和经验闭环。同机 Atoll、文件和浏览器已经验证；关闭入口不等于关停服务，但能否继续取决于内部执行与依赖是否仍有效，不能承诺无条件后台运行。

一期的部署边界分成两部分：本机执行面保存简历、任务、页面租约和签名经验缓存，并通过插件操作用户当前浏览器；CvMax 公共服务保存去事实值的页面经验。公共经验是产品能力，不保存用户简历或页面实际填写值。

二期增加独立的云端商业控制面：账号、登录会话、设备安装、权益、计费、岗位目录、推荐和后台运营。岗位目录使用 CvMax 自有 MySQL，并作为用户权益的数据来源之一；它只产生用户可选择的岗位清单，不能直接获得浏览器控制权。用户确认岗位后，仍创建一期已有的 ApplicationTask，进入相同的本机填写流程。

身份必须分开：`userId` 表示 CvMax 商业账号，`installationId` 表示一台 CvMax 安装实例，`atollPrincipal` 表示本机 Atoll 调用身份，`taskId` 表示一次业务委托。二期可以建立显式映射，但不能用其中任意一个冒充另一个，也不能让计费或岗位库成为 Atoll 的第二套身份、频道或 Agent 系统。云端/跨设备执行需另行验证。

验收顺序：A1 内部 Agent 一字段 → A2 Skill/Client 正式入口与任务控制 → A3 权限/文件/生命周期故障 → B 完整申请 → C 经验闭环 → D 安装、宿主支持与真实链路复验。未来 Web 接入单独验收，不能阻塞或冒充当前入口。具体证据见 SYSTEM-DESIGN 第 9 节。

被替换的原型、评审副本和旧直接工具调用夹具不保留在当前工程中。当前能力只以现行设计、实现和权威验证记录为准。
