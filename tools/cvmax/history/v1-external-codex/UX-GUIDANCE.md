# CvMax 状态与渐进引导 v1.0

当前规范，对应 Codex + Skill + CLI 的一期入口，取代 v0.1。产品范围与架构约束见 PRODUCT-DESIGN.md、ARCHITECTURE-FIT.md。以下行为为验收要求，旧原型仅验证了部分本地模拟。

## 1. 四条用户原则

1. 明确操作对象、授权范围、业务完成边界和停止条件。
2. 告知最近确认发生了什么、现在是否在执行、下一步由谁做。
3. 先给最多三个短阶段词，只展开当前一步；做完/核验后才展开下一步。
4. 已授权且助手能独立完成的操作，简短告知后直接做；不反复要求用户确认诊断、定位和核验。

主要交互在 Codex，插件做就地提示。CLI 返回机器可理解的事实，Codex 将其表达给用户，不能用模型措辞覆盖实际状态。

## 2. 一条状态的内容

对象（岗位/委托范围）＋最近确认事实＋下一步负责人＋一个主动作或“你暂时无需操作”。

例：“星河科技申请：基本信息已填写，当前需要网页登录。我已定位申请页，现在请在网站登录。”

状态记录包含 revision、lastConfirmedAt、来源与 freshness。断线显示“以下为最后确认状态”；旧事件不能覆盖新状态。“有记录”不等于“网站已存草稿”，“前端核验通过”不等于“投递成功”。

## 3. 状态和终止语义

| 状态 | 用户看到的事实 | 下一步/退出 |
|---|---|---|
| 尚未开始 | 前置条件未满足，没有开始写页面 | 一个当前修复动作或结束 |
| 正在填写/核验 | 正在做具体阶段 | 用户暂不操作，可暂停/停止 |
| 等你补充/登录/修改 | 明确缺哪项、在哪操作 | 当前一步完成后核验 |
| 等待页面/服务 | 有明确条件与剩余预算 | 条件满足继续，超限结束自动等待 |
| 已暂停 | 原因、范围与最后确认成果 | 用户主动暂停只由用户解除 |
| 需要重新核对 | 某动作结果未知 | 先只读观察，不能盲重试 |
| 部分完成 | 成果及未解决项可交付 | 手动处理、明确的新尝试或结束 |
| 待检查提交 | 已到最终复核边界且必填解决 | 用户检查并在原网站提交 |
| 已停止 | 不再派发新动作，在途结果单列 | 只读核对；重新开始是新 run |
| 无法继续 | 页面关闭、能力缺失或预算耗尽 | 具体人工出口或结束 |

执行结束、问题解决、网站提交分别记录。只完成当前页时不能称整份申请完成。等待用户可持久保留，不因时间过去视为同意/完成，也不能保持一个无限运行的工具调用。

停止必须说明当前申请还是整个委托。先阻断新动作，在途目标确认无旧写入后才引导用户修改；无法确认时提示风险目标。只读核对最多 30 秒，之后报告未知，不能再次上传/新增条目来“试试看”。

## 4. 当前一步的指导方法

“我们先检查连接 → 开启应用连接 → 核验后继续。”这是概览，不把十个技术步骤塞进三个长段。

- 助手阶段：“我先检查连接，你暂时无需操作。”随后实际检查。
- 用户阶段：“现在请在已打开的申请页完成登录。”密码和验证码只在网站输入。
- 核验阶段：“我来确认是否回到了原申请表单。”确认后再进入下一步。

用户说“好的”不代表已完成；用户说“做完了”触发重新核验，不无条件进入填写。当前步失败就在当前步说明原因和一个可执行出口，不重复完整教程。

没有可用路径时直接说目前无法继续，保留成果。核心契约不支持时告知停止，不指导用户去绕过系统权限或修改核心。

## 5. 缺项问答与数据范围

Codex 先解析用户指定简历，已有依据的事实直接用；缺少或歧义才问。可以一次询问同一阶段的两三个短问题，复杂决策分步处理，不要求用户再填一份简历。

默认答案仅当前申请；跨本批复用必须语义和适用范围一致且得到明确范围指令。不同国家工作许可不能合并，公司动机不能无条件通用。保存到用户长期本地资料文件需要明确指令，不自建资料管理产品或擅自覆盖原文件。

本地解析失败时保留原件和已知事实，只处理当前必要缺项。文件读取能力不可用则如实给当前可用替代，不能假装已解析。

## 6. 通知、恢复和学习反馈

仅在有意义的阶段变化、必要用户动作、完成或失败时告知。不逐字段刷消息，不在 Codex 和侧栏重复询问。恢复第一句是“上次停在 X，本次先核验 Y”，不重讲全套产品教程。

用户离开/关闭 Codex 对话后，不承诺后台唤醒外部窗口；回到对话时读取持久状态。活跃等待中的登录可自动核验继续，显式暂停和停止优先。

经验状态使用“已记录候选 / 验证通过 / 已隔离 / 已禁用”。一次成功不称已学会；停用错误经验不等于网页已修复。纠正收据说明作用范围、后续是否复用、当前页面是否仍需处理。

## 7. 验收断言

- 所有状态能回答：哪个岗位、最近确认什么、谁负责、下一步什么。
- 多个依赖失败时只给一个当前主动作；优先由助手诊断和核验。
- 停止后旧回执、刷新、登录、重启不能恢复自动写入。
- 未知结果在有界时间内结束自动核对，给网页定位或结束出口。
- 用户修改值优先；旧验证失效；恢复不把历史记录冒充当前网页。
- 无法实现某项业务时报告边界，不能以临时兼容方案脱离 Atoll。
- 键盘、焦点定位及必要状态播报需实际验证；不能据文字规范宣称无障碍合规。
