# CvMax 应用开发约束

先读 README.md、PRODUCT-DESIGN.md、ARCHITECTURE-FIT.md；用户旅程和交互规范分别在 USER-JOURNEYS.md、UX-GUIDANCE.md。它们是当前有效设计，history/、reviews/ 和旧 prototype 仅是历史材料，不得据其恢复已退出一期的功能。

本项目是以 Atoll 为基础寻找真实业务落地，不是先造独立填表产品再挂一个 Atoll 接口。业务完整与架构符合必须同时验收。

- 仅修改 tools/cvmax/，沿用 codex/job-application-autofill 分支。不得改核心设计、逻辑、代码、根依赖、注册、已有 UI 或 archtest，也不得直接修改核心数据库。
- 不因为代码放在本目录就认为合规：不得旁路身份/权限/消息链，不得另造核心生命周期或调度机制，不得伪造调用身份。
- 一期用户主入口是 Codex + Skill + CLI；CvMax 能力通过现有 Atoll MCP 扩展接入。客户端 Codex 与托管 Agent 身份有区别，遵循 ARCHITECTURE-FIT.md。
- 简历解析复用 Codex 本地能力；不新增资料中心。账号、推荐数据后台和支付在二期。持久经验与有界自进化是一期开闭环的必需能力。
- 只填写和核验，不最终提交。明确状态、范围、下一步责任与终止出口。复杂问题先给最多三个短阶段，只展开当前一步；能自主执行的已授权操作自行完成。
- 先实证架构契约闭环，再扩展业务。若需要触碰核心或绕开系统才能继续，停止依赖该能力的实现并给出实际调用、最小复现和边界说明，不自行采用临时兼容后门。
- 不把旧本地模拟、10 个角色推演、代码存在或单元测试通过说成新版真实链路已经通过。
