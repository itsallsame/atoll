# CvMax 用户旅程 v1.0

当前范围以 [产品设计](PRODUCT-DESIGN.md) 和 [架构契约](ARCHITECTURE-FIT.md) 为准。取代 v0.2；旧版推荐工作台、资料中心与侧栏主导流程不再属于一期。

## 1. 用户使用的是同一条系统链路

用户在 Codex 中安装/使用 Skill，指定本地简历。Codex 解析资料并调用 CvMax CLI，业务通过 Atoll 执行。用户不需要逐条运行命令，也不需要在另一个产品建立个人资料。

不同入口的差异是用户已有的上下文、授权对象与反馈位置，不是串行/并行策略。执行默认串行，状态与经验共用，不能为不同入口建设不同任务系统。

## 2. 场景地图

| 场景 | 用户当时在做什么 | 一期入口 | 反馈与完成出口 |
|---|---|---|---|
| A 当前页面 | 已浏览并决定申请当前岗位 | Codex：“用这份简历帮我填当前页面” | Codex 汇报；原页面定位/轻状态；最后在原页检查提交 |
| B 链接委托 | 已选好一个或多个岗位 | Codex：“这些链接都帮我填写” | Codex 给逐岗状态与页面入口；无须逐页重新启动 |
| D 恢复 | 回来处理原任务 | Codex：“继续刚才/昨天的申请” | 先显示最后确认成果，再核验当前页面 |
| C 推荐选择（后续） | 还在比较岗位 | 二期数据服务/选择体验，确认具体清单后进入同一执行链 | 保留选岗上下文，不作为一期导航或依赖 |

## 3. A：填写用户当前页面

1. 用户给出明确填写指令。助手自行检查目标页面；多个浏览器/tab 含糊时只澄清目标。
2. Codex 从用户指定文件提取事实与附件，不要求建立资料档案；已有明确事实直接用，有歧义再问。
3. 告知“正在处理远山科技的申请，填完后由你检查提交”；在 Atoll 中建立/附着申请。
4. 助手观察、复用经验、填写和核验。用户可继续浏览；目标 tab 的上下文变化会使旧定位失效。
5. 短缺项在 Codex 提问；网页操作由插件定位。回答后只重新处理受影响内容。
6. 返回已核验、保留、未解决及未知项，定位原申请页；只在确认最终边界时称整份填写完成。

一期不会因任意打开页面就自动开始。用户已明确委托当前申请后，登录跳转与已知中间页面无需再次表达同一个授权。

## 4. B：委托一个或多个链接

“这三个岗位都帮我填，用桌面的简历”已经是范围授权。助手解析、去重并冻结清单，逐个执行；只粘贴链接而没有意图时再澄清查看还是填写。

开始回执：“开始处理这 3 个岗位，填写后由你检查提交。”不为每个岗位重复问是否开始。公司/岗位未识别时如实显示识别中。

过程中只在重要状态变化汇报，例如“第 1 个已待检查，第 2 个需要登录，第 3 个尚未开始”。需要用户操作时默认暂停该委托；用户可说“先跳过这个”。跳过保留待办，批次结束不自动绕回；关闭/取消单项结束后可处理其余已授权项。

用户可暂停/停止整个委托、取消单项、新增岗位或指定不同附件。序号绑定当前可见清单，指代不清才询问。推荐刷新、页面跳转不能擅自扩大授权范围。

批次结束逐项计数，例如“1 项待检查、1 项待登录、1 项岗位已关闭；本轮自动处理已结束”。这不能称“3 项全部填写完成”。

## 5. 登录与人工控件处理

简要路径：“打开页面 → 你来登录 → 我继续填写”。助手能定位就直接定位，当前只要求在招聘站登录，不收密码或验证码。

登录完成后要核验原岗位、申请表单及可观察账号信息。账号明确不匹配时停下；身份不可确定且影响归属时只问当前会话是否用于本次申请。

在活跃执行/等待观察仍有效且授权不变时，确认登录后继续；用户明确暂停/停止不能被登录解除。Codex 对话已经结束则保留待恢复状态，用户回来后通过 CLI 查询重验，不承诺外部对话被自动唤醒。

控件不支持：先定位并告诉用户应选择什么及依据；用户修改后助手只读核验。多个人工步骤先给短概览，始终只展开当前一步。

## 6. D：恢复、停止与重复入口

恢复使用业务记录，不靠模型记忆。助手先报告“上次停在哪里”，再重新观察，明确区分历史已核验与当前已核验。网站草稿未保留时不能说已恢复全部内容。

- 同一申请再次发链接/打开两个 tab：关联同一 Application，只有一个活动执行租约。
- 改了简历：说明新版本和影响范围，不静默替换旧申请快照。
- 只是切换焦点：不暂停；目标页面导航到其他申请：废弃定位并重验。
- 明确暂停：只有用户明确继续才能恢复。
- 明确停止：阻断后续动作，有限只读核对在途结果；刷新、登录、重新打开都不能复活旧 run。
- 用户明确重新开始：新 run，仍继承申请级预算，先核对网页已有值。

## 7. 界面与通知收敛

Codex 是主要问答和状态告知位置；浏览器插件只保留具体页面的定位、简短状态、暂停/停止等必要操作。一个阻塞只产生一次主要提示，其他位置可同步状态，不重复索取相同答案。

一期不做资料中心、推荐工作台、申请历史管理站、经验仪表盘。查询和清理可由 Codex 调 CLI 完成。当前原型四个“场景按钮”只是旧版评审控制器，不是新版正式功能菜单。

## 8. 验收重点

A 验证“当前页无需换产品”；B 验证“一次委托无需逐页重述”；D 验证“恢复不丢上下文、不重复写、不复活停止”。C 留待二期，不把占位页面算交付。

每个场景都必须经相同的 Atoll 身份、频道和工具路径。未经系统的插件自启动、CLI 直连管理 API 或定时任务，不作为满足这些旅程的可接受方式。
