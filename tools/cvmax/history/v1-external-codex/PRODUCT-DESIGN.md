# CvMax 产品设计 v1.0

状态：当前有效设计，尚未实现生产产品。代码核对基线：Atoll `b447c91a`；分支：`codex/job-application-autofill`。本版统一此前讨论，取代 v0.3。旧文见 history/，架构硬约束见 [ARCHITECTURE-FIT.md](ARCHITECTURE-FIT.md)。

## 1. 项目关系与目标

先有 Atoll 系统，再选择招聘申请填写作为真实业务场景，最后以系统原生扩展方式构建 CvMax 产品。成功必须同时满足：业务核心流程完整可用，以及整条业务链路遵循 Atoll 的身份、权限、消息、工具接入与生命周期设计。

仅能填表但脱离 Atoll 运行，不算本项目成功；仅能调用系统但无法完成业务，也不算完成。不能通过“兼容层”“临时适配”“独立服务”等名称，为绕过系统的实现开例外。判断依据是实际职责和调用路径。

## 2. 用户需求与固定原则

| 用户要求 | 本版决策 |
|---|---|
| 找一个能在本系统落地的业务 | Atoll 是必需运行基础，先证明系统扩展契约，再扩充业务 |
| 新分支、核心绝不改动 | 仅在当前分支 tools/cvmax/ 内修改；核心不足即停 |
| 用户主要通过 Codex 使用 | Codex 对话是一期主入口；Skill 指导其调用 CLI |
| 简历可由 Codex 解析本地文件 | 复用宿主文件处理能力，提供本次申请事实及来源；不另建简历编辑器 |
| 当前网页与给定岗位是不同场景 | 保留页面就地委托、链接委托；共享执行记录，分别设计用户路径 |
| 用户说选定岗位都可以，就逐个填写 | 已明确范围后串行处理，不逐岗位重复询问启动许可 |
| 填写完成但不点最终投递 | 最终提交始终由用户在招聘站完成 |
| 登录后继续 | 检测阻塞解除并重验；不得覆盖显式暂停/停止 |
| 新页面自己分析、能填的填、不能填的告知 | 在已实现动作和预算内探索，逐项报告原因 |
| 经验积累加自进化必须有 | 一期包含本地证据、候选、验证、复用、隔离与回退 |
| 清楚的边界、状态、终止条件 | 代码约束执行；状态必须明确对象、事实、负责人、下一步 |
| 引导不要一次倾倒所有步骤 | 最多三个简短阶段，只展开当前必要动作；能独立做的由助手执行 |
| 账号、后台、最新岗位数据、支付在二期 | 一期不开发对应业务，也不以它们为启动条件 |

## 3. 一期产品形态和范围

安装组成：CvMax Skill、CLI、通过 Atoll 现有 MCP 类接入的应用工具、配套浏览器插件。本地应用进程和持久存储服务于执行与经验，不等于二期商业后台；进程生命期必须符合架构契约，不再发明系统调度器。

用户已有可用 Codex、Atoll 和目标浏览器。Skill 是工作流指令及配套资源，实际调用者是 Codex。CLI 使用命令和结构化结果表达能力，不让用户学习或逐条输入命令。

一期包含：

- 用户指定的本地简历/附件及本次资料快照；来源与不确定性保留。
- 当前页面与一个/多个已授权链接的填写，首版串行。
- 页面观察、字段映射、受限动作计划、执行后核验、动态表单与多页处理。
- Codex 中的必要缺项问答；登录/验证码/手动控件处理交接。
- 暂停、停止、断线重验、幂等恢复和逐项报告。
- 持久本地经验及有界自进化；最小安装与诊断、应用数据清理能力。

一期不包含：独立账号系统、简历管理中心、推荐工作台、收藏中心、商业后台、支付、跨用户经验库、全网岗位采集、自动登录/注册/验证码处理、最终提交、任意生成代码执行。

“资料补充”“连接修复”“登录”“停止接管”是流程内部状态，不是产品主导航。插件仅需连接/对象/当前状态、定位、暂停与立即停止等必要界面，不复制 Codex 对话和资料管理。

仅打开网页不等于授权填写。一期默认由 Codex 中明确的当前页/链接委托发起。已授权任务中的导航和登录恢复无需重复授权。此前讨论的长期站点自动触发模式保留为后续增强，须先证明系统原生事件、权限和唤醒路径，不能靠插件自行启动任务。

## 4. 核心完整流程

1. **接受委托。** 用户在 Codex 指定本地简历与当前页/链接；必要时澄清具体 tab、附件版本或岗位范围。明确指令直接启动，说明“填写和核验，最终由你提交”。
2. **检查前置条件。** CLI 经公开契约确认节点、调用身份、频道成员、工具可发现性和浏览器连接。能诊断的自行诊断；不支持的环境报告尚未开始。应用不安装升级或修补核心。
3. **准备本次资料。** Codex 利用可用文件工具解析简历，输出带 sourceRef 的事实快照、未确认项和附件引用。仅对歧义/冲突/无法确认的事实提问，不新增全面资料录入关卡。未知资格、薪资和意愿不能猜测。
4. **建立申请记录。** 固定授权清单、岗位身份、browser/tab/frame 绑定、资料版本、runId 和预算；重复委托关联现有申请。业务开始请求必须经过 Atoll。
5. **观察与规划。** 读取可见字段、选项、依赖与校验信息；先检索验证经验，再使用通用规则。无法确定的内容返回 Codex，由其提出结构化候选，应用验证可执行性与来源。
6. **执行并核验。** 按依赖执行受支持动作；保留已有用户输入，动作后检查页面是否接受。联动和导航后重新观察，不能复用过期定位。只自动点击已确认不会最终提交的下一步。
7. **必要交接。** 其他独立字段先处理。缺事实在 Codex 询问；登录/验证码在网站完成；不支持的控件定位给用户。每次只展开当前步骤，结果经核验后才继续。
8. **交付结果。** 确认整份已到最终复核边界、访问页必填全部解决且无未决操作，才是 ready_for_review。仅本页完成、部分完成、未知上传与不支持项分别报告。不得调用最终提交。
9. **形成经验。** 保留实际证据，生成有限动作配方候选；通过验证后逐步复用。学习整理失败单独报告，不撤回真实填写成果，也不能省略学习作为一期必需能力。
10. **下一岗位或结束。** 按已授权清单处理。遇到需要用户参与的阻塞默认暂停委托；用户可先跳过。岗位关闭/明确取消单项则结束该项并处理余项。最终逐项归账，明确自动执行已经结束。

主链：created → observing → planning → executing → verifying → ready_for_review。等待用户、等待页面、需要重验、暂停、部分完成、失败、取消为显式分支，详见交互规范。待用户不是无限执行中的命令。

## 5. 数据与执行规则

每份申请保存 Application、Run、资料快照、Attachment 引用、FormSnapshot、FillPlan、Operation、Question、Evidence 和 Experience；多岗位增加冻结清单 Batch。它们属于招聘领域模型，不是新的 Atoll Actor/频道/调度模型。

字段分别记录问题是否理解、事实是否具备、页面是否接受；结果至少区分 verified、preserved、missing_fact、needs_decision、ambiguous_question、option_unmatched、unsupported_control、validation_failed、unknown_effect、skipped_optional。

- 输入和计划严格 schema 校验；事实保留来源，推测不能转成已确认事实。
- 原件不修改；每次申请固定快照及附件，更新时显式说明受影响字段。
- 默认答案仅这份申请；用户明确指定才用于本批。长期个人资料复用的一期方式是用户指定本地资料文件，不建立 Profile 管理产品；不得擅自修改用户文件。
- 经验保存字段语义和动作方法，不把用户真实答案混进通用策略。
- 幂等请求、revision、documentEpoch 和执行租约防重复、过期操作及旧回执复活。超时不等于外部动作未发生；unknown 必须只读核对。
- 停止立即阻止后续动作，已派发动作单列；默认最多 30 秒只读核对，之后结束检查并报告未知。旧原型的 2 秒仅为演示时间。
- 初始应用预算草案：每字段最多 2 个策略、每页最多 3 次重规划、每申请累计 10 分钟活跃执行；不计用户等待，不因重启换 run 重置。实际默认值须通过评测。
- 没有明确独立操作边界时，不在结果未知期间继续可能冲突的动作。

## 6. 经验积累与有界自进化

一期必须验证三个能力：新页面上生成可执行候选、用真实动作结果校验候选、下次复用并在页面变化时失效。

流程：证据记录 → 同类经验检索 → Codex 提出新映射/有限动作组合 → 静态校验和测试页重放 → 实际受约束验证 → 经验升级 → 后续前后条件检查 → 失败隔离/回退。

候选和 verified 不是同一状态。初始升级门槛草案为 fixture 通过且至少两次不同 run 成功，没有未解决冲突；单次成功只记录候选。语义错误/用户纠正立即隔离，保留反例；连接故障不计为语义失败。

动作来自随应用发布的固定能力，如 setText、selectOption、searchSelect、uploadAttachment、inspectValidation、nextKnownStep。模型不能生成并直接执行任意 JS、扩大权限、修改 Skill 的强制边界、核心代码或测试。新控件超过能力时给手动出口；扩展动作属于后续应用版本开发。

自进化指应用经验在原有系统边界内改善，不是应用自改核心或自行发明新的执行通路。

## 7. 二期与未来入口

二期方向：产品独立账号、最新岗位数据服务、推荐选择入口、支付和后台管理。二期账号与 Atoll principal 如何对应须单独设计，不把产品账号自动视为系统身份，也不承诺新增了不存在的核心多租户能力。

未来推荐入口是“用户先选岗位再委托”，区别于“用户已在页面”和“用户提供链接”。必须保留独立选择体验，但当前不实现空壳后台或假推荐库；未来接入仍复用同一系统控制链和申请记录。

## 8. 阶段验收与不做虚假承诺

| 阶段 | 必须证明 | 不能据此宣称 |
|---|---|---|
| A 架构契约闭环 | Codex/Skill → CLI → Atoll → 应用工具 → 真实浏览器测试字段 → 核验结果，含身份拒绝、停止、重复与未知回执 | 全站适配、产品已上线 |
| B 完整申请 | 有状态测试页：本地简历 → 20+ 字段/重复经历/搜索下拉/附件/两页 → 缺项问答 → 登录恢复 → 最终复核前停止；含断线、用户修改和停止 | 一期完成，因经验尚未验收 |
| C 经验闭环 | 第二次复用、页面变化隔离、生成新候选、验证、纠正和回退；保留未用于调优的变体 | 任意网站都能填写 |
| D 可发布版本 | 一条明确 ATS 流程族实测、安装诊断、依赖说明、权限、数据清理、故障恢复和试用验证 | 未验证平台支持、真实提交成功 |

原 Greenhouse 流程族保留为首个支持候选，最终支持表由实际验收决定。真实站点测试须使用授权环境，不向真实岗位投递合成申请。

发布必须满足：关键事实无错误填写、所有缺项/未知项在报告中出现、没有自动最终提交或停止后复活、所有业务操作经过系统允许的边界、经验连续场景通过。性能和完成率须有真实样本与统计口径，不沿用旧设计目标数值冒充结果。

当时已有原型、设计文档和架构实验夹具。切片 A 因动态能力发现不一致受阻；真实填写、学习及生产链路均未交付。该阶段性验证流程现已退役。
