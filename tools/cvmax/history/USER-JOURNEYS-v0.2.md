# CvMax 用户场景与旅程设计 v0.2

日期：2026-09-05。状态：待实现的体验设计，对应 PRODUCT-DESIGN.md v0.3。

## 1. 产品组织方式

三种主动入口：就地填写、链接委托、推荐选择。一种贯穿所有入口的场景：继续未完成申请。它们共享资料、经验、申请记录及填写能力，但不要求用户从同一种界面开始。

目标体验：用户表达一次明确意图，系统完成能够独立完成的工作，只在缺少事实、需要决定或需要人工操作时打断。对话、按钮、结构化表单只是意图的不同输入方式，不强迫用户持续聊天。

“帮我投这些岗位”按产品说明执行到填写和核验完成，最终提交由用户操作。首次任务回执明确范围，不逐岗位重复征求开始许可。暂停、停止及调整范围始终可用。

## 2. 场景地图

| 维度 | A 就地填写 | B 链接委托 | C 推荐选择 | D 继续未完成 |
|---|---|---|---|---|
| 用户正在做什么 | 浏览公司申请页面 | 将已选岗位交给助手 | 比较产品提供的岗位 | 回来处理上次中断 |
| 已确定什么 | 当前岗位值得申请 | 一组链接需要处理 | 尚在选择，确认后确定范围 | 想继续已有申请 |
| 入口 | 扩展轻提示/已开启自动模式 | 对话粘贴链接 | 推荐列表和岗位详情 | 待办、历史、原申请页 |
| 主界面 | 招聘网站 + 轻侧栏 | 对话 + 任务摘要 | 岗位列表 + 详情/进度 | 原页面 + 恢复摘要 |
| 开始意图 | 点击填写或命中自动模式 | “帮我填这些链接” | “填写已选岗位” | 点击继续或完成已提示登录 |
| 过程反馈 | 小状态条 | 一条更新中的任务卡 | 岗位行更新 | 上次停在哪、这次补什么 |
| 完成出口 | 原页复核 | 摘要 → 对应页面 | 待检查列表 → 对应页面 | 回到原任务完成出口 |

底层首版可以串行执行，但不能要求 A 先建批次、B 手动逐页启动、C 用粘贴 URL 代替选岗体验。

## 3. A：用户就在招聘页面

| 阶段 | 用户体验 | 系统行为 |
|---|---|---|
| 进入前 | 在外部渠道找到岗位，自行打开链接 | 无需回产品首页 |
| 识别 | 显示“可帮你填写”和“填写当前申请” | 区分职位详情、真实申请表单、登录页、成功页 |
| 开始 | 点一次，或自动模式生效 | 显示“正在填写，随时可暂停”，绑定资料版本 |
| 处理中 | “已验证 12 项，正在处理教育经历” | 优先复用经验，自动探索新控件，不问用户技术策略 |
| 中断 | “还需要到岗时间和期望月薪” | 独立字段先做完，缺失问题集中问 |
| 完成 | “填写完成，请检查后提交” | 保留原 tab；只在确认最终边界时宣布整份完成 |
| 再次进入 | “这份申请已有记录” | 附着原任务并重验，不重复新增经历 |

自动模式为一次开启的设置：“打开已授权招聘站点的申请表单后自动填写”。开启时说明可能触发网站自动保存，最终提交仍由用户完成。站点访问权限与业务自动填写偏好分开记录，新站点仍需浏览器授权。

岗位详情页仅显示前往申请入口；浏览详情不自动启动填写。用户明确点击填写/委托该链接，才可从详情页推进。自动模式关闭后不再触发新任务，当前任务让用户选择继续或停止。

如果执行器正忙，提示“已识别，等待当前任务完成”，不抢占已有操作。用户手动输入优先，执行前发生值变化则跳过并重算。

## 4. B：用户交给助手一个或多个链接

| 阶段 | 用户体验 | 系统行为 |
|---|---|---|
| 进入前 | 已经筛选好岗位 | 不要求回推荐列表重新找 |
| 开始 | “这三个岗位帮我填一下” | 解析、去重、检查链接；明确指令直接开工 |
| 初始回执 | “已开始处理 3 个岗位，填完后由你检查提交” | 未识别链接显示域名和识别中，不编造岗位名 |
| 处理中 | 一条任务卡：“1 个待检查，正在处理第 2 个” | 管理申请 tab，不逐字段刷聊天消息 |
| 中断 | “星河科技需要登录” + “去登录” | 打开正确 tab，默认暂停当前委托 |
| 完成 | 分别列出待检查、待补充、无法继续 | 每项直达对应页面，不将未完成计为完成 |
| 再次进入 | 原对话任务卡仍可使用 | 从持久记录取进度，不靠模型回忆 |

只有粘贴链接、没有动作意图时，提供“查看岗位 / 帮我填写”选择；明确说“这些都帮我填”就是授权，不再重复确认。

支持“第二个先不处理”“把这个也加上”“暂停一下”。序号绑定可见列表稳定顺序；指代有歧义时才澄清。批次启动后范围冻结，用户新增/移除才变更。

示例：用户发三个链接 → 助手启动 → 任务卡显示“远山科技待检查、星河科技待登录、海岬软件未开始” → 用户点去登录并完成登录 → 星河科技继续填写。无需重述链接或已有答案。

## 5. C：用户从推荐岗位中选择

推荐列表提供岗位、公司、地点/远程方式、薪资（未知则写未提供）、简短推荐原因、来源、最近校验时间、收藏/不感兴趣及选择框。推荐原因应对应用户确认的资料和偏好，不展示无依据的匹配百分比。

详情提供职责、要求、明显不匹配项、原始来源和“加入本次填写”。回到列表时保留筛选与选择；浏览和收藏都不等于填写授权。

| 阶段 | 用户体验 | 系统行为 |
|---|---|---|
| 进入前 | “看看有没有适合我的岗位” | 根据确认过的偏好，从有来源的岗位库给建议 |
| 选择 | 勾选或说“这三个都可以，帮我填” | 绑定具体岗位 ID，不因推荐刷新改变范围 |
| 开始 | “已选 3 个 · 默认简历 · 填写已选岗位” | 点击启动；已有明确对话指令则直接启动 |
| 处理中 | 可以继续浏览，已选行显示申请状态 | 新推荐不自动加入委托 |
| 中断 | 顶部待办及岗位行显示待登录/待补充 | 点击进入带岗位上下文的处理界面 |
| 完成 | 待检查视图列出已填岗位 | “检查”回原申请页，与“岗位详情”分开 |
| 再次进入 | 保留收藏和申请进度 | 已处理岗位显示已有记录，防止重复委托 |

当前仓库分析尚未确认可用的岗位数据库，应用需新增 JobSource：来源 ID/URL、外部岗位 ID、公司、岗位、地点、描述、更新时间、申请 URL、有效性。

首版可由真实来源的导入/运营维护库供给，用偏好过滤与可解释排序；全网采集和复杂推荐模型不作为前提。上线不能用合成岗位冒充真实推荐。无数据时给链接导入入口；岗位开始填写前重验有效性，关闭则报告，不擅自替换。

## 6. D：继续未完成申请

这是 A/B/C 共用的恢复旅程，不是第四套任务系统。

| 再次进入方式 | 用户看到什么 | 后续行为 |
|---|---|---|
| 重新打开原申请页 | “上次停在学校选择，已完成 18 项” | 关联旧任务、重扫后继续 |
| 点待办“去登录” | 岗位、登录原因及正确页面 | 登录确认后恢复 |
| 历史点“继续” | 上次状态、未完成项、草稿是否可用 | 打开/复用页面，核验后推进 |
| “继续昨天那几个” | 唯一可识别则恢复，否则列候选 | 不重复创建申请 |
| 浏览器/本地服务重启 | “有 2 份申请等待恢复” | 重建绑定，不宣称站点一定保留了草稿 |

若资料版本已更新，默认保持原任务版本，提供“继续原资料 / 用新资料重新核对”；不静默替换已填内容。自动检测到登录完成可继续，但不能覆盖用户手动暂停/停止。

## 7. 中断的不同呈现

| 中断类型 | 必须提供 | A | B | C |
|---|---|---|---|---|
| 登录/验证码 | 岗位、原因、正确页面、继续入口 | 侧栏 | 任务卡 | 岗位行 + 待办 |
| 缺资料 | 问题、适用岗位、答案类型、保存范围 | 集中问题 | 一条集中问答 | 待办表单 |
| 需要决定 | 无法推断的事实或意愿 | 侧栏 | 对话 | 待办表单 |
| 控件障碍 | 定位、答案复制、手动处理与重验 | 原页定位 | 打开对应页 | 定位岗位 |
| 连接/模型不可用 | 已保存到哪、重试入口 | 状态条 | 任务卡 | 状态行 |

登录恢复需验证同一申请上下文、登录阻塞消失及预期申请表单出现。仅 URL 改变或登录按钮消失不足以判断；不确定时显示“我已登录，继续”。密码在网站输入，不让用户发给助手。

缺失问题集中询问；跨岗位复用必须同语义、同适用范围。到岗时间可建议复用至已确认的岗位组，不同国家工作许可不能合并，公司动机回答也不能通用。

首版按确认顺序执行，需人工处理时默认暂停当前委托。用户可明确选择“先跳过这个岗位”。执行策略留在后台，不作为产品主要导航。

## 8. 跨入口连续性

Application 是针对某岗位的持续业务记录；Run 是一次填写/恢复执行；Batch 是一次确认的多岗位委托；EntryContext 记录入口和反馈位置。一个 Application 可被所有入口引用，但最多一个活动 Run。

去重优先采用稳定岗位 ID + 公司/ATS 租户，URL 规范化只作辅助。身份不确定时提示可能重复，不强行合并。已提交的历史申请不能因打开链接自动重填。

必需切换规则：

- 推荐启动后打开申请页：侧栏附着现有任务，不再次触发。
- 就地填写时又发同一链接：对话返回已有状态。
- 两个 tab 打开同一申请：只一个执行，另一个提供定位入口。
- 网页手动修改后回列表：显示需重验，不保留过期全通过状态。
- 点击检查优先激活原 tab；tab 丢失则重新打开核验草稿，不伪造恢复成功。
- 填完未提交叫“待检查提交”；用户标记提交与网站确认页证据分别记录。

同一必要中断只产生一次主要提示。相关页在前台用页内提示，其他界面显示待办/通知；完成摘要也只产生一次，各入口读取同一结果。不逐字段通知，不反复催促。

可离开当前页浏览其他内容；执行仍要求浏览器、服务、Atoll 和模型可用。合盖、断线后的暂停如实显示，不承诺设备离线继续运行。

## 9. 页面信息架构

三种主表面：页面助手（状态条和侧栏）、委托对话（链接与持续更新任务卡）、岗位工作台（推荐、收藏、待处理、待检查、历史）。资料、附件、经验和设置共用。

工作台使用本应用自有扩展页面/前端，不改 Atoll 既有 UI。不同界面走相同应用协议，不引入不同业务真相。

下一轮场景原型应分别画三种表面的正常态、中断态、完成态；登录恢复为共用片段。此前生成图是早期视觉方向，尚未覆盖本设计的全部旅程。

经验反馈：A 在完成时轻提示已复用经验；B 在任务摘要里提供可展开的学习结果；C 的岗位列表不塞学习指标，报告和经验页可查看；D 旧经验失效时说明页面变化并重新识别。一次成功只能叫候选，新经验通过验证后才优先复用。推荐适合度与填表适配经验分开。

## 10. 场景验收

| 用例 | 通过条件 |
|---|---|
| A 自动模式 + 已授权申请页 | 无需再次点击/对话，随时可暂停 |
| A 浏览详情/已提交记录 | 不误触发 |
| A 资料足够 | 中途零必要交互，最终原页检查 |
| B 明确委托三个链接 | 一次授权启动，不逐个询问开始 |
| B 登录阻塞 | 正确定位、暂停，登录后无须重述任务 |
| C 列表刷新 | 只处理授权清单，新增推荐不被加入 |
| C 岗位无数据/已关闭 | 真实空态/关闭状态，不虚构替换 |
| D 重启恢复 | 保留身份、答案、资料版本，重验后继续 |
| 跨入口/重复 tab | 无重复执行和重复经历 |
| 手动暂停后登录完成 | 不擅自解除暂停 |
| 共用答案 | 同范围复用，跨国家资格问题不混用 |
| 通知 | 一个中断一个主提示，各表面一致 |

按入口分别统计：触发到开始的操作次数、必要问答次数、打断次数、恢复成功率、重复执行率、整份填写完成率。首版交付覆盖三入口与恢复；推荐先用真实导入库。全部限定应用层，公开契约不足需触碰核心时停止并报告。


## 11. v0.2：渐进引导和明确收尾

新增 [UX-GUIDANCE.md](UX-GUIDANCE.md) 作为三种入口及恢复场景共同的交互规范；[10 角色推演报告](reviews/SUMMARY.md) 记录本轮发现。

中断时先给最多三个短阶段概览，只展开当前一步，明确“助手正在处理/等你操作”；助手能独立做的直接执行。当前步核验成功后才展示下一人工步骤，不将集中收集事实误用为一次展示全部故障排除教程。

人工停止后不因刷新、重开、自动模式或登录成功复活；旧通知不能覆盖最新状态。仅本次默认仅这份申请，不自动进入长期资料。岗位关闭/明确取消单项终止并继续余项；先跳过保留待办，批次结束不自动绕回。具体边界以 UX-GUIDANCE 为准。
