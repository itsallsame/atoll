# CvMax 历史产品设计冻结候选 v2.2（AI-first）

日期：2026-09-05
状态：历史候选，已由 [当前产品设计](PRODUCT-DESIGN.md)、[系统设计](SYSTEM-DESIGN.md) 和 [开发计划](DEVELOPMENT-PLAN.md) 取代。本文的双入口与六旅程不属于当前一期实现声明。

## 0. AI-first 交互原则

CvMax 不是一个要求用户操作表单、菜单和工作台的传统 Web 软件。用户界面首先是 AI 对话：用户用自然语言表达目标、指向本地文件或附上资料；AI 自己检查上下文、调用 CvMax、解释状态，只在缺少事实或必须由用户完成登录时一次询问一件事。

- **Atoll Web** 指 Atoll 已有的对话入口，不另造一套 CvMax 操作后台。用户在对话里委托、回答、暂停和停止。
- **外部 AI** 也是对话入口。Skill/CLI 是 AI 调用 CvMax 的机制，不让用户手写命令、JSON、文件路径表单或岗位表单。
- **CvMax 远端 Web** 如果存在，一期只展示连接说明、任务事实、证据和结果；不承担资料录入、岗位录入、问题回答或流程配置。
- **Chrome 插件** 只展示当前任务现场状态、证据和紧急停止；不提供任务创建、资料填写或业务规划界面。
- 安装、诊断、恢复和卸载也由 AI 对话逐步引导。AI 能完成的步骤直接执行；只有浏览器安装/权限、网站登录等必须由用户完成的动作才交给用户。

按钮和状态卡只是对话的快捷回复与只读回执，不能演变成第二套业务操作界面。产品原型中的“场景/界面切换”仅供设计评审，不属于用户产品。

## 1. 产品一句话

CvMax 是 Atoll 上的求职申请业务服务：用户可从 Atoll Web 或自己常用的 AI 桌面发起同一任务，Atoll 内的 CvMax Agent 统一分析与决策，Chrome 插件只在招聘页执行受限填写并回传证据；系统在最终提交前停止。

## 2. 六条主旅程

| 编号 | 入口 × 场景 | 发起与资料 | 处理中与人工点 | 正常终点 | 异常终点 |
|---|---|---|---|---|---|
| J1 | Web × 当前页面 | 用户上传本次简历并说“填当前页，不提交”；插件返回当前活动招聘 tab 后建任务 | 自动观察、填写、回读 | `ready_for_review`，用户回原站检查提交 | 未配对为 `waiting_user`；活动页不在招聘范围或不支持为 `partial` |
| J2 | Web × 单链接 | 用户粘贴一个链接与本次资料；任务回执固定链接、资料版本和 taskId | 服务打开链接；登录、验证码留在网站；缺事实回频道只问当前一项 | 单申请交付复核 | 岗位关闭为 `failed`；未知页面效果为 `needs_reconcile` 后 `partial` |
| J3 | Web × 多链接 | 用户给出已确认清单；服务去重并显示冻结后的顺序，用户一次授权 | 严格串行；每项持续展示序号；可跳过当前项，不回头自动重试 | 批次报告逐项列出结果 | 人工阻塞默认暂停当前项；停止任务终止未开始项 |
| J4 | 外部 AI × 当前页面 | Skill 确认本次文件路径和当前页；CLI 只提交委托，不分析页面 | 内部 Agent 决策；宿主轮询同一 taskId 并用短消息转达当前一步 | 外部 AI 展示 `ready_for_review`，用户到原站检查 | 宿主无法识别 tab 时只澄清目标；连接失败进入 doctor |
| J5 | 外部 AI × 单链接 | 用户自然语言给简历与链接；Skill 提取带来源事实并建立单任务 | 用户可转到 Web 回答同一 questionId；另一入口刷新后不重复提问 | 任一入口看到同一最终状态 | revision 冲突先读取已采纳答案，不静默覆盖 |
| J6 | 外部 AI × 多链接 | 用户给出或确认清单；宿主展示数量和顺序后一次委托 | Atoll 服务串行执行；宿主只查状态、回答、暂停/停止 | 逐项统计待检查、跳过、失败和取消 | 外部 AI 关闭不撤销任务；依赖失效时持久等待 |

六条旅程共享约束：打开页面本身不是授权；答案默认只用于本申请；最终提交始终由用户完成；敏感凭证只输入招聘网站；跨入口使用同一 principal、taskId、questionId 和 revision。

## 3. 权威状态、负责人和终止条件

| 状态 | 最近确认事实 | 下一步负责人 | 可用动作 | 终止条件 |
|---|---|---|---|---|
| `draft` | 目标或资料尚未齐全 | 用户 | 补当前必要项、取消 | 任务未建立 |
| `queued` | 委托已持久保存，尚未执行 | 服务 | 暂停、停止 | 开始执行或被取消 |
| `running` | 指定申请正在观察/填写/核验 | 服务 | 暂停、停止 | 进入等待、交付或失败 |
| `waiting_user` | 已保留成果，并说明唯一阻塞 | 用户 | 回答、登录、跳过、停止 | 实际核验通过后恢复；用户回复本身不算通过 |
| `paused` | 新动作已阻断，保留最后确认成果 | 用户 | 明确继续、停止 | 继续创建新 run；停止关闭旧 run |
| `needs_reconcile` | 某外部动作效果未知 | 服务 | 只读核验、停止 | 30 秒预算内确认；否则以 unknown 交付 |
| `ready_for_review` | 必填项已核验且到最终提交边界 | 用户 | 打开原页检查 | CvMax 的申请工作结束 |
| `partial` / `failed` | 明确列出已完成与未解决项 | 无或用户 | 手动处理、新建任务 | 本 run 结束，不自动复活 |
| `cancelled` | 新动作已封锁；在途效果分别说明 | 无 | 新建任务 | 旧 run 永久结束 |

所有界面固定显示：对象、taskId、最近确认事实及时间、当前是否执行、下一步负责人。引导最多三个短阶段，只展开当前一步。系统能做的诊断和填写直接执行；需要用户时一次只给一个动作。

## 4. 首次安装、配对与退出

1. **选择频道**：在 Atoll 既有身份下创建或选择私有 CvMax 服务频道。只用 Web 的用户不安装外部 AI Skill。
2. **接入外部 AI（可选入口）**：针对已验证宿主安装 CvMax Skill 与 CLI。Skill 把自然语言变成公共业务命令，用户不手写 JSON。
3. **安装 Chrome 插件（页面执行必需）**：一次性说明招聘页面访问范围；任务中不再要求逐站授权，不读取密码、验证码，也没有最终提交动作。
4. **配对**：插件通过一次性配对码绑定当前 Atoll 身份和 CvMax 服务；不能仅凭本机端口认领任务。
5. **doctor**：顺序检查身份、频道、内部 Agent、应用工具、插件连接、当前页面；失败只展开当前修复动作，修复后从事实核验继续。
6. **首次任务**：用合成岗位页演示一项非敏感字段，明确“原型/演练”与真实任务的区别。
7. **卸载**：先阻断插件新动作并解除配对，再移除 Skill/CLI；让用户选择保留任务记录或请求删除允许删除的数据。卸载不声称撤回招聘网站已经收到的内容。

## 5. 三个界面的职责

| 界面 | 必须提供 | 明确不提供 |
|---|---|---|
| Atoll Web 对话 | 用自然语言发起任务、附上本次资料、回答问题、暂停/跳过/停止；状态卡只读展示 | CvMax 专用录入表单、独立资料中心、推荐与支付、绕开 Atoll 的新账户 |
| 外部 AI + Skill | 自然语言委托、准备获准本地文件、查询/回答/控制同一任务 | 第二套页面规划循环、直接控制插件、长期保存用户答案 |
| Chrome 插件 | 招聘页内常驻轻量进度卡：当前阶段、正在处理的字段、本组真实计数、已核验动作、最近确认、下一步负责人、收起和立即停止 | 任务创建、资料管理、智能规划、业务问答、最终提交 |

## 6. 原型覆盖与设计验收

交互原型以对话为中心，提供“申请任务 / 对话式安装”两个评审场景；可查看 Atoll 对话、外部 AI 对话和招聘页插件三个表面，并用同一 taskId 演示登录交接、事实缺失、重新核验、交付与停止。原型中的评审切换器不属于最终产品。

产品设计冻结前必须满足：

- 六条旅程均能从发起走到明确终点，并有登录、缺事实、页面不支持、未知效果和停止出口。
- 三端对同一状态表达一致；关闭入口、重复回答、迟到回执都不能恢复已停止 run。
- 10 个独立角色首轮模拟中没有未解决的高优先级问题；修改后由同一角色脚本复验。
- 原型明确这是产品设计，不把模拟当成技术可行性或真实插件证据。

## 7. 批次、暂停与跨入口一致性

批次拥有自己的状态，Application 各自拥有独立状态、最近事实和终止原因。`ready_for_review` 只结束当前申请；服务随后进入下一项。只有全部申请进入终态，Task 才显示汇总。跳过当前项写入 `skipped` 后推进索引；停止整个任务保留已经完成的结果，把在途项标为 `cancelled` 或 `unknown_effect`，把未开始项标为 `cancelled/not_started`。

暂停必须保存 `applicationId + runId + phase + lastConfirmedFact`。继续产生新 run，先核验页面与事实，再回到原阶段；不能退回登录或重新填写。三个界面都从同一 revision 投影状态。界面上的旧按钮在状态变化后立即失效，并把键盘焦点送到新的状态摘要或唯一主动作。

任务建立后连接掉线时：若没有在途页面动作，进入 `paused_dependency` 并保留检查点；若存在尚未收到证据的页面动作，进入 `needs_reconcile`。连接恢复只创建新 run 做只读核验，确认页面、账号标识与最后效果后再回到原阶段；超过 30 秒仍无法确认就以 `unknown_effect` 结束当前申请。恢复连接本身不会重放任何写动作。

## 8. 资料权限与数据生命周期

界面不能使用“仅你可见”作为笼统承诺。必须就近列出可访问主体、用途、期限和撤销后遗留：

| 数据 | 可访问主体 | 用途与默认期限 | 撤销/删除后 |
|---|---|---|---|
| 原始简历附件 | 用户、获准 Atoll Agent、CvMax 文件工具 | 当前任务解析；任务进入终态 7 天后自动删除 CvMax 草稿副本 | 删除 CvMax 副本；外部 AI/OS 原文件不受影响 |
| 事实快照与答案 | 用户、获准 Agent、应用工具 | 当前申请；终态后保留 30 天用于恢复与纠错；批次复用需显式选择 | 可提前删除；审计引用只保留字段类型与结果，不保留字段值 |
| 任务、问题与操作证据 | 私有频道成员、Agent、应用工具 | 状态恢复、冲突与审计；默认保留 180 天 | 到期删除内容，保留 Atoll 必需的最小安全审计事件 |
| 页面适配经验 | CvMax 服务 | 只保存页面结构、动作策略和结果，不保存用户答案；保留到规则退役后 30 天 | 语义错误立即隔离；退役期满删除 |
| 招聘网站草稿 | 招聘网站 | 站点自身保存规则 | 停止或卸载不能撤回网站已接收内容 |

外部 AI 委托前必须显示准确文件、提取字段类别、接收方和目标站点；身份证件等高敏感字段单独确认。插件权限按域名、tab、DOM 读取和获准字段写入展示，支持本次授权和撤销。登录凭证只由招聘网站接收；CvMax 不采集密码或验证码。是否能从浏览器权限层禁止最终提交要在技术阶段验证，产品层承诺是“不会规划或执行最终提交动作”。

卸载依次阻断新动作、解除设备配对、撤销站点权限、移除插件和 Skill，然后让用户选择保留任务记录或请求删除附件/事实；返回逐项回执，并明确招聘网站草稿和 Atoll 必需审计记录仍可能存在。

## 9. 经验积累与有界自进化的用户状态

| 状态 | 用户文案 | 行为与终止 |
|---|---|---|
| `candidate` | 新识别方法，尚不会自动复用 | fixture 与不同 run 验证后才升级 |
| `reusable` | 已验证，可在匹配页面使用 | 页面条件一致才执行 |
| `degraded` | 检测到页面变化，旧方法已停止写入 | 重新观察并尝试通用策略 |
| `quarantined` | 方法疑似有误，已对后续任务停用 | 用户纠正或语义错误立即进入 |
| `retired` | 已回退或被替换 | 不再被新任务选择 |

页面变化只终止旧经验复用，不直接终止申请。通用策略仍失败、预算耗尽或控件不支持时，当前 run 才以 `partial` 结束。字段级“这项填错了”会先暂停写入，展示当前值、事实来源和所用经验；接受纠正后隔离经验、重新观察、改写并回读。经验保存失败单独报告，不改变申请填写结果。

## 10. 可访问性与真实输入

所有选择组使用正确的 button/tab/list 语义与 `aria-selected`/`aria-pressed`；插件进度卡使用服务给出的 operation index/total 渲染文本和 progressbar，不根据耗时伪造百分比。状态变化使用 live region；暂停/停止/错误提供完整状态摘要，用户无需从页首重新遍历。卡片可收起但执行中保持可恢复，最终状态禁止再次停止。

缺项必须使用带 label 的真实输入，显示 questionId、revision、答案来源和作用范围。回答先进入“已接收，正在核验”，页面回读通过后才能完成。当前页面由插件返回浏览器当前活动 tab：未配对时引导一次性配对；活动页不在招聘范围时说明当前状态并让用户切换页面。
