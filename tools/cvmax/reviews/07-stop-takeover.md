# 用户07：停止与接管推演

仅依据两份设计文档；以下为假设场景与文档推演，未测试真实软件。事实：设计已有本地停止闸门、人工输入优先、回执丢失不重放及恢复重扫。

## 6步旅程
1. 假设我发现学校填错，同时简历上传已派发但无回执，立即点“暂停”。
2. 我需要先看到“新动作已阻止；上传结果待核验”，而非笼统“已暂停”。
3. 助手说明概览“①确认停住 ②修改学校 ③核验并决定继续”，当前只展开第一步，自行读取可取得的状态。
4. 确认学校无在途写入后，定位该字段让我改；附件保留待核验，不催我重传。我改完点“已修改”。
5. 助手重验学校与附件；我选择“停止此次填写”，随后关闭并重开页面。
6. 我期待仍显示已停止、学校最新核验结果和附件是否落地；助手可核验，重新写入必须等我明确重新开始。

## 设计缺口
- **P1｜暂停/停止的恢复边界未贯通。** 原文：[状态定义](/Users/ahaha/work/xiebo/atoll/tools/cvmax/PRODUCT-DESIGN.md:130)、[再次进入](/Users/ahaha/work/xiebo/atoll/tools/cvmax/USER-JOURNEYS.md:89)、[自动模式](/Users/ahaha/work/xiebo/atoll/tools/cvmax/USER-JOURNEYS.md:39)。触发：停止后重开，通用“重扫后继续”是否重启已取消任务不明确；第95行仅明确登录不能解除停止。验收：暂停展示继续，停止展示重新开始；重开、自动模式、登录均不得解除人工停止，首次恢复仅观察。
- **P1｜接管安全时点缺少可执行反馈。** 原文：[手动接管](/Users/ahaha/work/xiebo/atoll/tools/cvmax/PRODUCT-DESIGN.md:70)、[在途动作](/Users/ahaha/work/xiebo/atoll/tools/cvmax/PRODUCT-DESIGN.md:134)。触发：点暂停便改学校，但旧动作可能随后完成；执行前比值不能解释已派发动作。验收：逐个标明在途目标，明确哪些字段可立即修改；目标尚有写入时先收束或核验，确认后定位让用户改，晚回执不能覆盖人工改值的最新结论。
- **P2｜停止后的附件未决项缺少收尾出口。** 原文：[未知效果](/Users/ahaha/work/xiebo/atoll/tools/cvmax/PRODUCT-DESIGN.md:205)、[上传不可撤销](/Users/ahaha/work/xiebo/atoll/tools/cvmax/PRODUCT-DESIGN.md:217)。触发：只说“可能无法撤销”，我仍不知道能否离开及谁继续查。验收：助手先只读核验并显示核验时间；有完成证据则更新结果，无证据到有界检查截止点便标“结果未知”，结束自动检查，给定位网站确认入口；不重传、不以取消冒充上传失败。

## 渐进对话
我：“填错了，停！”助手：“已阻止新动作。接下来确认停住、修改学校、核验结果。现在我先核对在途动作；简历上传尚未确认。”核对后：“学校已可修改，已为你定位，改好点‘已修改’。”我完成后，助手才核验：“学校已核验；附件仍待确认，我继续检查。”我：“停止此次填写。”助手：“已停止自动填写；附件结果仍未知。重开页面会保留此状态，由你决定是否重新开始。”
