# 用户04：选择困难的求职者

仅依据两份设计文档推演，以下是待验证的体验风险，并非真实故障。行号路径均相对 tools/cvmax/。

## 七步旅程

1. 我比较远山、星河、海岬三个岗位，重点看远程要求与薪资。
2. 逐个看详情后返回，勾选三项；尚未授权填写。
3. 推荐刷新、排序变化，我想确认刚才选的仍是这三项。
4. 点击“填写已选岗位”，知道助手负责填写核验，我负责最终提交。
5. 远山填好；星河开始前发现已下架，我等待系统说明海岬是否继续。
6. 我决定取消海岬，担心取消按钮会把远山成果也清掉。
7. 我打开远山申请页检查提交，期待列表明确说明另两项已终止，没有待我处理的隐藏任务。

## 高价值问题

1. **P2｜已选范围可见性。** USER-JOURNEYS.md:67、72 已保证选择保留及 ID 绑定，但刷新后选中行可能离开视野。我无法快速核对授权对象。改善：固定“已选3项”入口，展开公司、岗位、地点和移除按钮，刷新后保留可见清单。验收：换排序和筛选后仍能一处核对三项；授权只含该清单。

2. **P1｜下架后的下一步不明确。** USER-JOURNEYS.md:81、111 规定关闭则报告、人工处理默认暂停，但未说明已关闭岗位是否阻塞余项。我会等一个不可能继续的岗位。改善：明确关闭为该项终止，保留记录并自动处理其余已授权岗位；显示“星河已关闭，无需你处理；正在处理海岬”。验收：关闭项不写页面、不替换，后续授权项继续，总数分列关闭项。

3. **P1｜取消单项缺少完整回执。** USER-JOURNEYS.md:59、74 与 PRODUCT-DESIGN.md:134 提供范围变更和停止边界，但推荐行未定义操作。我不确定取消是移除勾选还是停止填写。改善：未开始显示“取消此项”；执行中显示“停止此项”，立即阻止新动作，回执说明已填内容保留、在途结果是否待核验，其他岗位继续。验收：两种状态分别取消，仅目标岗位停止；刷新后不复活，余项成果保留。

4. **P2｜混合结局缺总览。** USER-JOURNEYS.md:76、152 覆盖待检查与关闭状态，未约定关闭、取消后的统一收尾。我可能把“待检查1项”误解为还有两项在跑。改善：固定批次摘要“1项待你检查提交，1项已关闭，1项已取消；助手处理结束”。验收：三个原始岗位均可追溯，终止项不进入待办，唯一下一步直达远山原页。

## 分步引导示例

“接下来：①我核验并填写三项；②有必要时请你补充；③你检查并提交。现在第①步：正在核验远山，星河和海岬尚未开始；你可继续浏览，随时取消单项。”遇到下架时仅展开当前状态：“星河已关闭，无需操作；我继续海岬。”
