# 用户03：批量委托中的登录中断

独立设计情境推演，未进行真实测试。角色：忙碌上班族，交办三个岗位，希望少交互。

## 七步推演

1. 我说“这三个都帮我填”。助手直接开工，先给三步概览：依次填写 → 处理必要待办 → 我检查提交；当前只展开第一份。
2. 第一份核验完成，任务卡标“待检查提交”；第二份开始，第三份未开始。不能说已经投递。
3. 第二站要求 SSO/验证码。助手暂停整个委托，说明第三份也在等我，并定位登录页；登录由我完成。
4. 我登录正确账号；确认仍是原岗位且表单出现后，助手重扫续填并更新任务卡，不再问开始许可。
5. 若无法检测，我点“我已登录，继续”；仍无法确认时应说明具体障碍及下一步，不能反复让我点。
6. 我去开会或合盖。回来应看到最后更新时间、离线/待登录状态、已保存成果和恢复入口；手动暂停后即使登录成功也不能自动继续。
7. 若账号错误，应先换账号再核验；若我说“先跳过第二个”，助手处理第三个，最后区分两份待检查与第二份待处理，说明如何恢复或终止。

## 有证据的问题

**P1｜账号校验缺口。** `tools/cvmax/USER-JOURNEYS.md:107` 的恢复条件只覆盖申请上下文和表单。SSO 自动选到另一账号时仍可能满足条件，我不知道资料将归谁。改善：发现可见账号不符时暂停换号；首次无法确认归属时只问一次，不收密码。验收：错误账号不触发资料写入，换号后重扫恢复。

**P2｜“先跳过”的后续范围不明。** `tools/cvmax/USER-JOURNEYS.md:59,111` 定义冻结范围和跳过，却未说明该项保留待办还是移出、何时回访。我可能以为第三份之后会自动回来。改善：明确“暂留第二份待登录，先做第三份；第二份等待你恢复”，区分暂停整批、跳过单项、停止整批。验收：跳过不冒充完成、不静默删项；最终摘要保留恢复入口。

**P2｜手动恢复失败缺少出口。** `tools/cvmax/USER-JOURNEYS.md:107,150` 有“我已登录，继续”，验收仅要求登录后恢复。SSO 返回错误页或检测持续失败时，下一步仍不清楚。改善：按钮先重验；失败指出“尚未回到该岗位申请表”，提供定位申请页、先处理下一份或停止。验收：重验失败不写入、不循环催登录，任务卡明确等待谁做什么。

## 分步引导对话

助手：“已开始这三份：①依次填写，②处理必要待办，③你检查提交。现在填写第一份。”

助手：“第一份待检查。第二份需要你登录，整个委托已暂停，第三份尚未开始。点‘去登录’；确认成功后我会继续。也可先处理第三份。”

用户：“登录好了。”

助手：“已确认回到第二份申请表，正在继续填写，之后处理第三份。”

无法确认时：“还没检测到申请表。请点‘返回该岗位’完成跳转，再点‘重新检查’。”
