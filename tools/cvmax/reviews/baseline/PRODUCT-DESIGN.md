# CvMax：产品与应用设计 v0.2

日期：2026-09-05。基线：Atoll b447c91a；分支：codex/job-application-autofill。

本文是待实现的设计及验收契约，不表示对应功能已交付。CvMax 为暂用工程名。

v0.2 补充三种主动入口（就地填写、链接委托、推荐选择）及跨入口恢复场景。完整旅程、授权范围、通知与去重规则见 [USER-JOURNEYS.md](USER-JOURNEYS.md)。下文核心流程是共用执行能力，不要求所有用户从相同界面开始。

## 1. 产品目标与首发边界

帮助个人用户在招聘页面完成真实、可核验的资料填写；遇到未知页面能够探索，遇到缺失信息能准确提问，遇到技术障碍能保留成果并交接；每次操作形成可复用、可纠正的经验。

首发形态：Chrome 扩展侧边栏 + 本地应用服务 + 用户自己的 Atoll 节点及现有 agent。先提供个人本地版本，不把多租户云服务纳入首发。模型可能在云端运行，不能宣传所有数据不离开设备。

首发必须包含：资料导入及确认、单页/多页填写、缺失信息补充、结果核验、手动接管、恢复、持久经验、新策略生成与验证、经验失效和回退；页面内入口、链接委托入口及推荐选择入口共享申请记录。推荐入口先接入真实来源的导入/维护岗位库。

首发不包含：全网职位采集和搜索、批量自动提交、自动注册/登录、绕过验证码、自动点击最终提交、跨用户共享学习库、在线执行模型生成的任意脚本。支持用户确认范围后的多岗位填写，用户在招聘页面自行提交；产品分别记录“填写完成”和“用户报告已提交”，不能混淆。

首发保证范围：一个通过验收的 Greenhouse 申请流程族，加上通用 HTML/常见受控表单能力。Greenhouse 是初始适配目标，不承诺覆盖所有企业定制和全部版本；实际发布支持表以验收页面指纹为准。Workday 等更复杂平台后续逐个认证。陌生页面允许探索，但不宣传任意网站百分之百完成。

## 2. 核心流程及完成标准

核心用户故事：用户导入简历，打开招聘表单，点击填写；工具填写已有事实，询问缺失信息，用户回答后继续；发现所有当前及前序已访问页面的必填问题均已解决，停在最终提交前；第二次遇到同类页面使用已验证经验；页面变化时识别失效并重新学习。

### 2.1 安装及准备

1. 安装扩展和应用服务。应用安装向导检测 Atoll 版本、连接、登录、目标私有频道、MCP 工具可发现性及 agent 可用性。
2. 通过现有 /ws 管理词注册外部 MCP 工具，不写核心注册表文件；安装器只修改本应用配置及用户授权创建的运行时声明。
3. 扩展与本地服务一次性配对，绑定浏览器身份；按需申请目标站点权限。失败时显示具体问题和重试入口。
4. 导入 PDF/DOCX 简历，抽取成资料草稿。用户确认姓名、联系方式、经历等关键事实后成为可自动填写的资料版本；解析失败可手动录入，不能堵死主流程。
5. 选择默认附件；明确哪些资料会发送给当前 agent。工作许可、薪资、迁移意愿等未提供事实保持 unknown。

### 2.2 一次填写

1. 用户点击“帮我填写”、明确委托链接、确认推荐岗位，或命中已开启的站点自动填写模式：复用/建立 Application 记录，固定当前 tab、frame 范围、站点授权、资料版本和一次 run；重复入口命中同一活动 run。多岗位委托冻结 Batch 清单，首版逐项执行。
2. 观察：解析字段、分组、候选选项、校验条件、现有内容、页面步骤，生成脱敏结构指纹和观察版本。
3. 检索：按平台、结构、语言、控件和适用条件寻找经验；不只依赖域名或 URL。
4. 规划：确定性规则处理已知字段；agent 只处理不确定映射或文字草稿，返回结构化候选。服务检查资料存在性、问题适用范围、类型、枚举值和动作权限。
5. 执行：按依赖顺序分批填入可确定字段。用户已有非空值默认保留；冲突进入待处理列表。遇到缺失字段仍继续其他独立字段。
6. 核验：每个动作后检查接受状态。联动改变字段集合后重新观察；通过验证的条目才标记完成。
7. 补充：将缺失项集中显示，用户可回答、选择“仅本次”/“保存到资料”、跳过可选项，或去页面手动填写。回答进入新资料版本，仅重算受影响字段。
8. 多页推进：只有已认证且被判定为非最终提交的下一步动作可自动执行；不确定按钮由用户点击。每次导航后重新观察，不复用旧元素引用。
9. 复核：已访问页面的必填项都有结果、没有未决错误、流程已到可识别的最终复核/提交边界，才显示“填写完成，请检查后提交”。未知流程终点只能显示“本页已完成”。
10. 学习：将执行结果持久化，再从结果生成候选经验。经验整理失败不撤销已填写结果，显示“经验整理待重试”，本地待处理队列稍后续做。

### 2.3 明确三个判断

每个字段分别保存：是否理解问题、是否拥有有依据的答案、页面是否接受操作。不用一个 success 布尔值代替它们。

完整结果包括：verified、preserved、missing_profile、needs_decision、ambiguous_question、option_unmatched、control_unsupported、validation_failed、unknown_effect、skipped_optional。

必填项不允许通过“跳过”变成成功。只填完部分字段的 run 必须标记 partial 或 waiting_user，不能计入完整完成率。

## 3. 产品界面及交互

| 界面 | 主内容 | 主操作与状态 |
|---|---|---|
| 首次连接 | 本地服务、Atoll、模型、浏览器连接状态 | 连接、修复指引、重新检测 |
| 委托对话 | 已确认链接、更新中的任务卡、必要问答 | 发起委托、调整范围、定位登录页、检查结果 |
| 推荐岗位工作台 | 岗位来源/详情、推荐原因、选择和申请状态 | 选择岗位、填写已选、处理待办、检查申请 |
| 我的资料 | 联系方式、工作/教育经历、偏好、附件；显示来源与确认状态 | 导入、修改、确认、导出、删除 |
| 当前申请侧边栏 | 公司/岗位、当前步骤、已完成与待处理数量、简洁活动说明 | 开始、暂停、继续、停止 |
| 待处理面板 | 按“缺资料/需要决定/操作障碍”分组；点击定位网页字段 | 回答、保存范围、手动处理、重新检查 |
| 填写结果 | 完成项、保留项、未完成项、生成回答标识 | 定位复查、重新检查、返回网页提交 |
| 申请历史 | 每次 run 状态、资料版本、恢复入口、结果报告 | 继续未完成申请、删除、导出 |
| 经验记录 | 已学习场景、验证次数、失败原因、失效/回退记录 | 禁用经验、撤销本次学习、查看来源 |

默认侧边栏宽约 380px，可缩放；不遮挡字段定位。进度用“已验证 18 项，待补充 2 项”，不用无法解释的百分比。等待时显示实际阶段和取消入口。状态同时用文本与图标表达；键盘可操作，定位后焦点可返回。

用户修改网页时，以用户输入为先：执行前比对原值，变化则跳过并重算。手动接管暂停当前 tab 的自动动作，其他 tab 不受影响。恢复后重新扫描。

用户通常只看到“已学会这类学校选择，下次优先使用”等简短信息，不需要理解 actor、MCP 或模型上下文。

## 4. 应用架构与核心零改动约束

### 4.1 部署组成

扩展包含侧边栏、后台连接管理和 content scripts。独立 Node/TypeScript 应用服务包含 MCP 门面、确定性流程控制器、浏览器连接端点、资料库、经验库和本地 SQLite 存储。它通过已有 mcp class 成为 tool actor；既有 agent 负责语义推理与调用工具。

控制链：扩展使用用户已认证的 Atoll /ws 发起 agent.ask；agent 通过现有 call_actor 调用应用 MCP 工具；应用服务只执行状态允许的动作；浏览器回执返回应用工具并最终进入 Atoll 消息响应。

扩展与服务的私有连接只承载配对、受 run 授权约束的页面观察/执行回执以及附件数据；不得成为可任意启动业务动作的第二套管理 API。应用的开始、回答、继续、暂停、停止都走 /ws 请求。页面侧另有立即停止执行的本地闸门，即使 Atoll 断线也能停止新动作，之后补报状态。

无须新建内置 Go class，也无须修改 tools/all 注册文件。MCP 服务接受显式 principal/channel 配置，每个个人安装独立进程及存储，不假定 MCP tools/call 自动提供 Atoll principal。首发不复用一个服务实例给多个用户。

### 4.2 职责

| 组件 | 唯一职责 | 不承担 |
|---|---|---|
| 既有 Atoll | 身份、频道、消息、工具路由、agent 生命周期 | 招聘字段、ATS 规则、学习策略 |
| 既有 agent | 为陌生字段提出映射与操作计划、起草回答 | 裁定动作成功、任意改变 run 状态 |
| 应用流程控制器 | 状态迁移、计划检查、执行授权、恢复、预算 | 修改核心、相信模型自报的成功 |
| 浏览器执行器 | 预置动作、局部等待、页面观测与证据 | 自由代码执行、自动最终提交 |
| 经验模块 | 检索、候选生成、验证、升级、失效、回退 | 用其他用户答案填当前申请 |

### 4.3 存储所有权

Atoll 账本拥有调用、身份与消息记录；应用 SQLite 拥有业务 run、operation、资料与经验的权威记录，两者分别拥有自己的事实。消息返回 runId/revision/摘要，作为业务状态在该时刻的收据，不能另起一份可独立修改的同名 run 真相。

不假定外部 MCP 服务能直接调用 Go Sys.State/Resource。首版通过应用工具访问自己的存储，不读写 Atoll SQLite。若后续采用公开资源接口存储，必须证明契约可用并明确迁移所有权，不能双写两套权威状态。

每个状态迁移与事件在应用 SQLite 同一事务提交；外部通知采用 outbox，可重复发送，通过事件 ID 去重。执行器回执先持久化再向上游确认。大附件留在应用文件库，通道只传引用和元数据。

### 4.4 文件边界

计划将全部新文件置于 tools/cvmax/：extension/、service/、contracts/、fixtures/、tests/、scripts/、设计文档。独立 package.json、锁文件、构建和迁移；不改根依赖、Makefile、go.mod、go.sum、现有 Go 文件、protocol/runtime/lib/platform/registry/drivers/archtest 或现有 UI。

开发校验脚本检查相对基线的所有变更路径，只允许 tools/cvmax/；发现越界即失败。若现有公开工具路由、身份范围或生命周期不足以形成核心闭环，记录实际失败契约并停止，不加核心后门、不放宽架构测试。

## 5. 业务协议与流程状态

下列是新 MCP 工具建议名，实际 Atoll 消息名使用已有 MCP name 前缀规则。所有 schema 必须严格校验，拒绝额外字段。服务不在一个未返回的 MCP 请求内等待 agent 再来调用自己，避免递归等待。

| 工具 | 输入要点 | 输出与作用 |
|---|---|---|
| profile_import / profile_confirm | 文件引用/草稿、版本 | 资料草稿/确认版本 |
| run_start | clientRequestId、浏览器/tab 绑定、profileVersion | runId、revision、初始状态 |
| run_inspect | runId、expectedRevision | 表单快照摘要、未知字段、nextAction |
| run_propose | runId、snapshotId、资料版本、结构化计划 | 经校验的 planId 或拒绝原因；不执行 |
| run_execute | runId、planId、expectedRevision | 执行批次收据及逐字段结果 |
| run_answer | runId、questionId、答案、保存范围、expectedRevision | 新 revision、受影响项 |
| run_resume / run_pause / run_stop | runId、expectedRevision | 状态和下一步 |
| run_status / run_report | runId、sinceRevision | 持久状态/完整结果/学习进度 |
| experience_feedback / experience_disable | ruleVersion、具体纠正或原因 | 新候选版本/禁用状态 |

慢操作采用“短调用启动 operation → 返回 operationId → 后续查询/收取”的协议，不依赖 MCP 调用持续几小时。用户等待结束后以新的 agent.ask 加 runId 继续；首版不承诺节点重启后无人值守自动继续写网页。用户重新打开侧边栏即可看到待恢复任务并继续。

状态主线：created → observing → planning → executing → verifying → ready_for_review。

分支：planning/verifying → waiting_user；executing → waiting_page；任何活动状态可进入 paused；连接丢失进入 disconnected；页面或动作结果不明确进入 needs_reconcile；不可恢复错误进入 failed；用户停止进入 cancelled。

resume 必须先到 observing/needs_reconcile，不能直接 executing。ready_for_review 后若用户修改页面，验证结果失效并重验。学习状态单独维护 pending/candidate/validated/failed，避免学习队列阻塞填写交付。

每次写请求带 expectedRevision，版本不一致返回 revision_conflict。每个浏览器 tab 同时只允许一个活动执行租约；租约包含 epoch，旧连接/旧计划不能继续执行。已发出的原子操作可能完成，停止不宣称能撤销外部网站已发生的行为。

## 6. 数据模型

| 实体 | 必须包含 |
|---|---|
| ProfileVersion | profileId/version、确认字段、原始来源、更新时间；事实与偏好分开；unknown 不等于 false |
| ProfileFact | path、value、sourceRef、confirmedAt、适用国家/时间、有效性 |
| Attachment | id、文件名、类型、大小、内容哈希、本地引用、解析状态 |
| Application | applicationId、principal、稳定岗位身份、来源入口、历史 run、当前状态、提交证据类型 |
| Batch | batchId、已授权 applicationId 清单、稳定顺序、范围版本、执行策略及总体进度 |
| ApplicationRun | runId、applicationId、batchId（可选）、entryContext、principal/channel、browserSessionId、tabBinding、profileVersion、state、revision、预算、当前页及报告 |
| FormSnapshot | snapshotId、documentEpoch、origin、平台/结构指纹、分组、字段及约束、观察时间 |
| Field | fieldRef、frameRef、groupPath、语义线索、控件类型、现值摘要、required、options、验证规则 |
| FillPlan | planId、snapshotId、profileVersion、steps、依赖图、答案来源、经验版本、前后条件 |
| Operation | operationId、stepId、动作、before 摘要、预期 after、epoch、pending/sent/verified/unknown/failed、证据引用 |
| Question | questionId、fieldRefs、问题、原因、必填性、答案类型、候选及保存范围 |
| Experience | ruleId/version、scope、匹配条件、适配动作模板、验证谓词、来源、证据、状态、回退版本 |
| Feedback | run/field/rule 引用、原结果、用户修正、语义原因、是否确认可学习 |

每次 run 固定资料版本。用户回答保存为新版本后显式切换，记录受影响字段和已填旧值，不静默改写已完成页面。历史经验保存 profilePath 而非某个人的实际答案。问题去重包含国家、时间与问题语义，不只比较文本。

## 7. 页面理解、执行与核验

页面观察优先 label/ARIA/name/autocomplete/分组/选项，DOM 与可访问语义共同形成字段描述；不把整页脚本、隐藏输入、密码、cookie 或无关正文送给模型。页面内容仅作为资料，不能改变 agent 的权限或工具策略。

映射层次：精确已验证经验 → 平台规则 → 通用字段规则 → agent 候选 → 用户澄清。对学历、日期、工作许可等做独立的业务约束检查；模型自报 confidence 只能用于排序，不直接授权执行。

预置动作集合：setText、setChecked、selectOption、searchSelect、setDate、ensureRepeatItem、uploadAttachment、waitForCondition、inspectValidation、nextKnownStep。没有 submit、eval、任意网络请求或文件系统写入动作。

每步具有 precondition/action/postcondition，依赖图保证国家先于省份、在职状态先于结束日期。ensureRepeatItem 根据记录语义与已存在条目差异决定新增，不使用无条件 clickAdd。

字段引用只在当前 documentEpoch/snapshot 内有效。导航、大规模重渲染、用户切页使计划失效；局部 DOM 变化按目标字段前置条件重验，避免无关动画造成无限重扫。

验证等级：文本值保留且无本地错误；下拉选项确实选中并形成控件状态；重复条目数及内容一致；上传出现完成状态并匹配附件信息。只读到输入文本不等于搜索下拉已经接受。无法观察内部状态时报告验证有限，关键必填控件必须由用户确认。

最终提交前无法证明服务器最终接收，报告应明确“前端验证通过”。网站输入框可能自动保存，开始填写即可能向该站点发送资料；不能把“未点击提交”描述为“数据未发送”。

## 8. 经验积累与自进化

### 8.1 学什么

三类持久经验：语义映射（问题 → profilePath）、操作方法（控件 → 预置动作组合）、失败/修复（在何种条件下某方法无效）。每条经验有精确 scope：个人、站点/平台、语言、表单结构、控件特征和版本。

首发学习范围为单个用户本地，不自动上传社区。个人事实、个人偏好、个人问题答案与可泛化规则分库存储。

### 8.2 如何进化

1. 每次成功、失败、纠正写入不可变 Evidence 记录，含动作、条件、结果及来源。
2. 学习模块从差异提取新规则候选，或请求 agent 组合已有动作形成新 recipe。候选必须关联实际观察，不接受无来源规则。
3. 静态验证：schema、动作白名单、资料路径、允许站点、步骤预算、无循环/任意代码、前后条件充分。
4. 在本地交互 fixture 上重放，检查该规则是否完成目标和是否影响其他字段。静态 DOM 快照不能替代有状态控件测试。
5. 只读 shadow 匹配新页面，确认适用范围；候选在实际 run 使用时遵守与现场探索相同的执行门槛，不获得额外权限。
6. 初始提升规则：fixture 通过 + 至少两次不同 run 的真实验证成功 + 无未解决冲突，才升为 validated；只有一次成功可在严格相同指纹下作为 candidate 再验证。该阈值是首版策略，不是正确性证明。
7. validated 规则进入检索优先级；运行时仍检查前后条件。任一关键语义错误/用户纠正立即隔离该版本；同一指纹连续两次控件失败也隔离，恢复到最后可用版本或重新探索。

候选、验证通过、隔离、废弃均保留版本链。用户纠正后至少生成针对该字段的负例和新候选；单次修正不自动扩展到所有相似问题。网络断开与语义错误分开计数，避免连接故障污染经验质量。

### 8.3 自进化的边界

首发通过有界、非图灵完备的声明式动作配方实现新操作方式；解释器和每个可执行动作随扩展打包。模型不能动态扩大动作集合，也不能修改核心、测试或安装文件。

若新控件超出动作能力，产品给出具体障碍，保存失败样本并允许手动完成。后续新增动作需要应用版本开发、测试和发布；不能把“未来可能支持任意控件”当成首发保证。

Chrome 对扩展远程托管执行代码有约束，所以自动生成并在线执行任意 JavaScript 不作为上线架构。声明式规则也需要在发布前核对商店可审查性要求，不能宣称使用 JSON 就天然合规。

## 9. 中断、恢复与预算

| 故障 | 设计行为 |
|---|---|
| 重复点击/重复请求 | clientRequestId 与 operationId 去重，同一任务返回现有状态 |
| 填好但回执丢失 | 标为 unknown_effect；重读页面，比较前后条件，不盲目重放 |
| 用户换页/关闭 tab | 废弃定位，暂停；恢复需重新绑定并确认岗位上下文 |
| 应用/节点/扩展重启 | 从 SQLite 恢复 run，取得新 epoch，重扫后继续；不依赖后台 JS 内存 |
| 用户自行填写 | 保留用户值、撤销旧计划相关步骤、重新验证 |
| 模型不可用 | 已确定规则仍可处理独立字段；未知项停在可恢复状态 |
| 需要登录/验证码 | 暂停并交给用户，完成后重扫 |
| 控件无法操作 | 定位、说明原因、提供对应答案复制、手动处理后验证 |
| 学习失败 | 填写报告照常交付，证据与待学习条目留存并重试 |
| 磁盘写失败 | 停止派发新动作；不能无持久记录继续写页面 |

首版默认每个字段最多 2 次不同策略、每页最多 3 次重新规划、每次 run 自动执行活跃时间上限 10 分钟（不含用户等待）；超过后显示成果与障碍，允许用户显式继续并增加预算。循环由状态机限制，不依靠 prompt 自觉。

浏览器 service worker 会休眠；连接重新建立后交换 session/epoch 与未决 operation，不能认为旧 socket 存活。暂停应立即阻止下一动作，已开始上传等动作可能无法撤销，向用户说明实际状态。

## 10. 数据保护与信任边界

每个用户独立私有频道、独立应用存储和服务实例。应用协议不接受调用方任意覆盖 principal/channel；配对令牌绑定浏览器，会话命令绑定 origin、tab、run、epoch。端点只监听 loopback，校验具体扩展来源与令牌；拒绝陌生页面和其他未配对扩展。

这里只隔离普通网站和未配对客户端；不宣称能抵御拥有同一用户 shell/root 权限的本地进程，Atoll 的同节点信任边界不因本应用改变。

资料导入只产生草稿；模型生成文字标注为草稿并在首次填写前让用户确认，不虚构资历、资格或意愿。模型读取字段问题时不需要个人值；生成文字时仅发送用户选择的相关事实。

应用操作日志默认记录字段路径、动作和错误，不记录值；敏感原值和截图另存受保护证据区。默认不持久保存整页 HTML/截图，需要反馈样本时先让用户预览。应用资料和附件提供导出、删除；学习证据默认保留 30 天，报告默认 90 天，用户可调整；已抽象规则保留到删除/失效，删除原始资料同时清除应用内关联敏感证据。

Atoll 的消息账本可能保存工具请求中的内容，本应用删除不等于清除了既有账本或模型服务记录。尽量只在账本传资料引用与脱敏结果，在产品说明中明确这条边界；如果产品要求全链路可擦除而公开接口不支持，属于必须停止并报告的核心契约问题。

## 11. 上线、运维和版本

安装包包括扩展、应用服务和诊断工具；复用用户既有 Atoll/agent，不自动升级节点。以基线版本和经过实测版本建立兼容表，未知版本先运行契约自检。

应用拥有自己的 DB migration、备份和版本回退；修改前备份，回退失败可恢复应用快照。Atoll home 不由本应用迁移或修复。若节点升级破坏契约，暂停业务并报告兼容问题。

基础监控：连接状态、run 状态时长、逐类错误、操作重试、经验命中/失效、模型调用次数与可获得的用量。没有 provider 用量时显示 unavailable，不伪造费用。默认本地统计，用户显式选择才发送脱敏诊断。

发布渠道：先可安装的本地试用包和受控内测，再扩展商店提交；商店通过是发布条件，不是本设计已经取得的事实。浏览器权限按需申请；iframe 需要额外来源授权时解释用途。

## 12. 上线验收与评测设计

### 12.1 必须贯通的一个标准场景

使用合成个人资料、可交互测试招聘站和真实 Atoll 节点：导入简历并确认 → 20+ 字段含重复经历/搜索下拉/日期/附件 → 两页申请 → 两个缺失问题 → 用户回答 → 恢复填写 → 最终复核前停止 → 保存经验 → 第二次申请复用 → 改动字段结构触发失效 → 探索并验证新经验。

中途强制断开一次扩展连接，至少一次模拟动作成功但回执丢失。必须恢复且没有重复经历、不覆盖人工输入、不点击最终提交。不能只做静态页面演示。

### 12.2 评测分层

1. schema/状态机/经验生命周期单元测试。
2. 有状态浏览器 fixture 集成测试：受控输入、portal 下拉、异步候选、iframe、重渲染、附件失败、联动隐藏字段和终步歧义。
3. 真实 Atoll + 外部 MCP + agent 工具桥的端到端测试；主路径测试可使用确定性 agent stub，另以真实已配置 agent 验证语义链路。
4. 至少 30 个分层验收场景：12 基础、8 动态控件、6 中断/人工干预、4 学习/隔离。另留 10 个不参与规则调优的 holdout 变体测泛化，不用训练样本重复证明自进化。
5. 对首发声明支持的招聘流程，在授权的测试页面/账号上做真实浏览器验证；开发自动化不向真实岗位发送测试申请。

### 12.3 发布闸门（目标值，不是当前测量值）

- 核心标准场景每次发布全链通过；所有安全性不变量和恢复用例通过。
- 姓名、邮箱、联系方式、工作许可等关键事实在验收集中零错误填写；任一错误阻止发布。
- 已支持场景，用户补全事实后的整单 ready_for_review 比例 ≥95%；明确统计分母，排除的站点/人工动作单列，不用部分完成冒充成功。
- 缺失必填项和技术障碍在验收集中 100% 出现在报告。
- 复用实验比首次探索减少至少 50% 的陌生字段推理调用，且字段正确率不下降；此为同难度配对实验，不假设对任意新页面成立。
- 页面变化用例能隔离过期规则；用户纠正用例在下一次相同语义场景不再复犯。
- 本地暂停阻止新动作目标 <1 秒；常规交互确认目标 <1 秒；20 个标准字段无上传/模型调用时验证完成目标 P95 <15 秒。测试报告注明机器、浏览器和样本量。
- 所有代码变更路径限于 tools/cvmax/；兼容检查和应用独立构建通过。

## 13. 实施切片与停止条件

切片 A：公开契约贯通。独立 MCP 工具注册 → 现有 agent 调用 → 已配对扩展观察/写入一个测试字段 → 验证收据返回；证明无需改核心。必须同时验证消息大小、文件传递、取消、超时和恢复入口。失败涉及核心则停止。

切片 B：完整核心流程。实现资料导入、run 状态机、通用动作、缺失问答、两页填写、报告、断线恢复。此时还不能对外称为完整产品，因为学习未交付。

切片 C：经验与自进化。候选生成、证据存储、重放验证、复用、纠正、隔离和回退；贯通第 12.1 节的连续场景。这是首个内部可验收版本。

切片 D：上线准备。实际 ATS 认证、扩展打包、安装升级、资料导出删除、诊断、holdout 评测、内测与商店审核。完成后才称为首发版本。

不在本轮直接实现这些切片；本轮交付设计。任何切片若必须修改核心逻辑/设计/代码，停止并给出“调用契约、最小复现、当前阻塞、应用层替代路径及限制”，不得自行修核心。
