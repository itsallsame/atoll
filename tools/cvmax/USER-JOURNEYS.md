# CvMax 用户旅程 v2.0

同一服务，当前由外部 AI + Skill 进入，未来保留 Atoll Web 接入口。产品范围以 [PRODUCT-DESIGN.md](PRODUCT-DESIGN.md) 为准，实现边界见 [SYSTEM-DESIGN.md](SYSTEM-DESIGN.md)。

## 1. 入口与场景矩阵

| 业务场景 | Atoll Web（未来） | 外部 AI + Skill（当前） | 共同结果 |
|---|---|---|---|
| 当前页面 | 在服务频道说“帮我填当前页”；插件返回浏览器当前活动招聘页 | 对宿主说“用这份简历填当前页”；Skill 通过服务解析活动 tab | 同一内部 Agent 接受委托，在原招聘页交付复核 |
| 单/多链接 | 粘贴链接并明确填写，提供本次资料 | 自然语言给已选清单与资料 | 冻结清单、逐项状态、人工阻塞与跳过 |
| 恢复/接续 | 打开原服务频道，查询指定任务 | “继续昨天那份申请”，先查服务记录 | 同一 taskId、相同问题与最后确认成果 |
| 推荐选择（二期） | 从推荐数据确认清单 | 宿主展示获准数据后确认清单 | 选岗是上游，确认后复用同一服务 |

## 2. 首次使用

未来 Web：复用既有身份和服务频道展示信息并接入对话，当前不作为完成声明。

外部：宿主接入适配 → 连接同一 Atoll 服务及既有身份 → 发委托。对用户只展开当前必要步骤；CLI 不让用户手写业务 JSON。不同桌面的安装方式按验证过的适配提供，不假装任意宿主都兼容。

内部 Agent、MCP 工具和浏览器配对是服务就绪条件，诊断尽量由工具完成。当前明确只支持外部 AI + Skill；Web 缺少必要文件或控制能力时如实显示未来能力。

## 3. 外部 AI 委托与未来 Web 接续

1. 用户：“用这个本地简历填这三个链接，别提交。”宿主整理本次事实和附件引用，发结构化委托。
2. 内部 Agent 持久接受，返回 taskId、冻结清单及“填写后由你检查提交”。外部宿主此后查状态，不自行逐字段规划。
3. 服务先完成第一岗，到第二岗发现需要登录，记录 Question 和 waiting_user；第三岗尚未开始。主入口显示：“第一项待检查，第二项需要登录；现在请在招聘页登录。”
4. 用户转到 Web，同身份同频道查询原 taskId，看到同一状态；在招聘页登录后于 Web 说“已登录”。服务读取实际页面核验，满足条件且没有暂停/停止才继续。
5. 用户回到原外部对话，宿主刷新状态显示问题已解决，不再次要求登录、不重新创建任务。

登录只有网站处理，不传密码和验证码。登录中账号/岗位发生变化则停在核验；“好的”不是已完成证据。

## 4. 未来 Web 发起、外部 AI 补充

用户在 Web 交付一个岗位和获准资料；内部 Agent 解析并执行。服务发现缺少到岗日期，保存 questionId。用户随后在自己的 AI 桌面查询同一任务，回答该问题；CLI 带 questionId、适用范围与 expectedRevision 提交。

若 Web 同时已回答，返回已解决或版本冲突。外部宿主展示已采纳的答案，不能静默覆盖。答案只作用于明确范围；修改已有答案需要一次明确的新指令并核验受影响计划。

该场景留给未来 Web 验收，不能以“外部宿主能解析文件”替代 Web 自己的资料交付路径。

## 5. 使用入口的关闭与故障

关闭外部对话/Web 不是撤回委托。内部服务仍有效且无需用户参与时可按既有授权继续；不保证已关闭的第三方桌面收到通知。需要用户时停在持久 waiting_user，用户从任一入口回来查询。

Atoll 节点、工具、浏览器或授权失效必须阻断依赖它的后续动作，记录最后确认状态；服务恢复后先核对，不因重新连上就自动重放。委托已保存但 Agent 未唤醒时显示任务待继续/需要处理，不能显示“正在填写”。

## 6. 暂停、停止、跳过和并发入口

- 当前申请/整个委托必须可区分；含糊的“都停下”按可确定的当前委托范围立即阻断，不等待模型做复杂解释。
- 用户暂停只能由明确继续解除；停止的旧 run 不能恢复，重新开始用新 run。
- 多入口同时控制时以服务事务和 revision 为准；停止后迟到回答、计划或回执不复活执行。
- 结果未知时先只读核验；最长 30 秒后交付 unknown 并结束本轮检查。
- 用户先跳过登录项：保留待办，处理余下授权项；批次结束不悄悄绕回。
- 重复链接先关联业务记录，多个 tab 不产生多个并发申请执行器。不同资料或会话冲突需明确目标。

当前 Client 的停止命令直接抵达领域闸门，插件立即停止是现场紧急出口。未来 Web 的忙时停止必须单独实测，不能用中断 Agent 输出代替。

## 7. 完成的表达

申请到最终复核且无必填/未知阻塞：“填写与核验完成，请在原网站检查后提交。”

只有部分字段核验：“已完成基本信息；工作许可尚未确认。当前请确认这一项。”

批次结束：“1 项待检查、1 项待登录、1 项岗位关闭。本轮自动处理已结束。”不称三项全部成功或已经投递。

已停止但在途上传未知：“已阻止后续动作；刚才的附件上传结果尚未确认。”不以“已停止”暗示已撤回网站收到的内容。

## 8. 后续原型与角色复验范围

历史原型呈现 Web、外部 AI 和招聘页插件三个表面；当前实现收敛为外部 AI 与招聘页插件。原型只保留设计证据，不复制商业后台或资料中心，也不代表 Web 已实现。

十角色模拟已经用于产品设计阶段的问题发现；它只能验证设计推演。当前实现另以自动化回归和真实插件链路验收，未来 Web 与新增宿主仍需各自实测。
