# CvMax：Atoll 上的招聘填写服务

当前实现范围：**外部 AI + 唯一 CvMax Skill 是一期入口，内部 Agent 统一业务决策；用户私有服务维护任务和 ResumeFact，CvMax 公共经验服务维护跨用户经验。** Web 只保留未来入口位置，本期不实现。Client/CLI 与 Chromium 插件是服务组件；Microsoft Edge 为主验收浏览器，Chrome 保留兼容。先有 Atoll，再落地业务；业务开发仅在应用层。

业务修改目录 tools/cvmax/，分支 codex/job-application-autofill，核对基线 b447c91a。用户明确授权的唯一系统修复例外及其范围见 [AGENTS.md](AGENTS.md)；不因此扩大其他核心修改权限。

## 实现状态

当前填写策略为“冻结用户补充资料与本次所选简历 → 建立不可缩减的 ApplicationPlan → 网站原生简历上传/解析优先 → 按责任账本核验整份计划 → 对仍未处理的事实继续受限自主填写或给出证据化例外”。用户选择的 ResumeFact 可以覆盖招聘网站中更早的旧简历内容；解析触发和少量关键事实正确都不等于完成，项目、校园、附件及其他适用事实必须逐项结算。

简历现按 `ResumeFact` 管理：一份简历原文件及其结构化投影构成一个独立事实单元。`resume-save` 首次保存或生成新 revision，`resume-list`/`resume-get` 返回不含事实原值的摘要；`submit` 统一使用 `resume: {id, revision}`。旧的顶层 `resumeId + resumeRevision` 仅作兼容别名，两种形式不能混用。Client 会在打开招聘页面前校验参数、简历版本以及解析后的事实数和附件状态；无效引用不会创建任务。任务创建时冻结所选 revision，不能从其他简历补值，本次岗位答案也不会回写简历。

当前已进入应用层开发，已有应用服务、Client/CLI、可加载到 Edge/Chromium 的插件和 AI-first 原型。`cvmax install` 通过 Atoll 公开的声明和成员命令安装或升级 Hosted Agent 与 stdio MCP Service；`cvmax doctor` 检查正式链路。插件 v0.2.29 在招聘页打开后立即显示准备状态，并把岗位详情页与最终填写页分成两种页面入口；观察层以 entry_surface（投递入口）和 resume_surface（简历处理）表达业务页面；登录、验证码和真正覆盖主内容的弹窗是正交阻塞状态，窄固定章节导航不再被当作 modal。冷学习在结构证据矛盾、动作无效果或覆盖层分类不确定时可按需获取一次受任务租约约束的私有截图；插件临时激活精确任务标签页完成截图后恢复用户原标签页，截图不作为动作验证，也不进入公共 Page Model 或 Recipe。扩展为截图声明 `<all_urls>`，但运行时协议仍仅接受任务授权的精确 HTTP/HTTPS tab、URL 和短租约。页面先按可执行入口确定表面，URL 仅在入口证据不足时辅助判断，只有 resume_surface 中的字段才进入填写流程。执行时展示服务驱动的大区块进度，并用高亮框和连接线指向当前区域，同时保留核验计数、下一步负责人和立即停止。招聘域名和公司流程不写入插件静态配置：用户提交的链接或明确选择的当前页形成任务级页面授权；入口、表单、站内简历恢复路线和过渡弹窗都属于同一招聘系统 Recipe 状态图并由公共 Registry 动态发布，因此新增网站和 Recipe 无需更新插件或重启 Service。插件只保留稳定的观察、有限动作、窗口转换、通用交互激活、私有视觉取证、解析握手、进度和停止原语。多岗位只冻结顺序，到当前 Application 开始时才打开对应页面。Client 先把授权请求保存到应用服务，只向 Hosted Agent 发送 request ID，避免在自然语言轮次里传输整份简历事实。已知页面通过一次 `run_recipe` 工具调用连续完成入口转换、原生解析关键事实核验或必要的 Recipe 填写、回读和终止，异常再交回 Hosted Agent。插件不保存独立业务状态。自动化测试统一放在 `test/`，作为正常开发质量检查；不再维护独立验证流程、阶段性验证 Skill 或证据目录。

Page Model + Recipe 层按招聘系统和确定页面状态工作：插件上报原始结构锚点，Page Model 将其映射为标准简历区块；入口、简历处理、弹窗、分区与填写再被编译到一张 Recipe 有向状态图。每次核验成功的动作立即成为转换；下一次精确命中时由 `run_recipe` 程序化执行，不启动 Hosted Agent，也不计算字段相似度。缺少映射或转换时才交给 Agent 学习。公共 Page Model 与 Recipe 一起进入 CvMax 独立 MySQL，经多个 installation 的匿名核验后发布签名 release；Service 热加载新 release，新增公司无需更新插件或重启 Service。

当前已验证服务自动打开或定位招聘标签页、停止闸门、合成环境下的页面家族识别、字段级经验升级、兼容漂移复用、失败隔离，以及重复项目/校园区块的动态添加、填写和独立回读。终止判断以冻结 ApplicationPlan 的完整责任账本为准；选填和未标必填的网站专属字段允许留空，法律同意等最终人工步骤随 `partial` 结果交付，不会让任务无限等待。最终提交调用为零。历史真实站点记录只代表当时页面与旧完成口径，不能替代新的 TC-001 冷学习和独立重放验收；证据和限制见 [真实页面验收记录](REAL-SITE-ACCEPTANCE.md)。生产级多站点覆盖和最终发布验收仍未完成。

产品设计、技术验证与工程设计已经形成开发基线。后续实施继续遵守 [总计划](DEVELOPMENT-PLAN.md) 的阶段门禁；若应用需求必须修改未授权的 Atoll 核心能力，该路径立即停止。
