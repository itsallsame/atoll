# CvMax：Atoll 上的招聘填写服务

当前实现范围：**外部 AI + 唯一 CvMax Skill 是一期入口，内部 Agent 统一业务决策；用户私有服务维护任务和 ResumeFact，CvMax 公共经验服务维护跨用户经验。** Web 只保留未来入口位置，本期不实现。Client/CLI 与 Chrome 插件是服务组件。先有 Atoll，再落地业务；业务开发仅在应用层。

业务修改目录 tools/cvmax/，分支 codex/job-application-autofill，核对基线 b447c91a。用户明确授权的唯一系统修复例外及其范围见 [AGENTS.md](AGENTS.md)；不因此扩大其他核心修改权限。

## 实现状态

当前填写策略为“网站原生简历解析优先 → CvMax 回读纠错与补填 → 原生解析不可用或无效时自主填写”。策略只在高置信度解析入口且不会覆盖无来源旧值时启用，解析触发不等于成功，仍以页面回读为准。

简历现按 `ResumeFact` 管理：一份简历原文件及其结构化投影构成一个独立事实单元。`resume-save` 首次保存或生成新 revision，`resume-list`/`resume-get` 返回不含事实原值的摘要；`submit` 可指定 `resumeId + resumeRevision`。任务创建时冻结所选 revision，不能从其他简历补值，本次岗位答案也不会回写简历。

当前已进入应用层开发，已有应用服务、Client/CLI、可加载的 Chrome 插件和 AI-first 原型。`cvmax install` 通过 Atoll 公开的声明和成员命令安装或升级 Hosted Agent 与 stdio MCP Service；`cvmax doctor` 检查正式链路。插件 v0.1.25 在招聘页打开后立即显示准备状态；执行时展示服务驱动的大区块进度，并用高亮框和连接线指向当前区域，同时保留核验计数、下一步负责人和立即停止。Client 先把授权请求保存到应用服务，只向 Hosted Agent 发送 request ID，避免在自然语言轮次里传输整份简历事实。已知 exact 页面通过一次 `run_experience` 工具调用连续完成解析、经验填写、回读和终止，异常再交回 Hosted Agent。插件不保存独立业务状态。自动化测试统一放在 `test/`，作为正常开发质量检查；不再维护独立验证流程、阶段性验证 Skill 或证据目录。

经验层按页面家族和结构版本工作：动态岗位 ID、查询参数和框架生成 ID 不影响稳定页面命中；已知站点可从用户给的详情链接安全解析到唯一的已验证申请表路由。跨用户权威经验存入 CvMax 独立 MySQL，经多个独立安装实例的匿名核验后按 candidate → canary → released 发布；失败率越界后自动 suspended。本地只执行验签后的 released 配方，并保存有期限的公共缓存。`partial` 也可贡献已核验字段；精确版本返回确定性无值动作建议，兼容版本只返回仍能唯一绑定的稳定字段并报告结构漂移。经验动作仍由内部 Agent 通过普通工具门禁执行并重新观察，不保存用户事实值、简历、附件或自由文本反馈。此前真实验收的字节申请页 13 条策略已作为运营审核种子版本签名迁入公共库。

公共状态不返回简历事实原值或内部预算键，只报告事实数量、是否有附件和进度计数。后续 Agent 回合确需映射时才调用内部 `task_context` 一次。MCP 结果的文本部分仅返回完成摘要，完整数据只保留一份结构化内容，避免每轮重复吞吐。

当前已验证服务自动打开或定位招聘标签页、停止闸门、合成环境下的页面家族识别、字段级经验升级、兼容漂移复用、失败隔离，以及两个字节校园招聘岗位的插件专用真实填写：基础资料、附件、2 条实习和 6 条项目均完成独立回读。终止判断以已证明的必填阻塞为准；选填和未标必填字段允许留空，法律同意等最终人工步骤随 `partial` 结果交付，不会让任务无限等待。最终提交调用为零。经验层已有 13 个 reusable 字段策略；后续正式链路命中 exact 版本时先执行网站原生解析，再把经验用于核对和补填。证据和限制见 [真实页面验收记录](REAL-SITE-ACCEPTANCE.md)。生产级多站点覆盖和最终发布验收仍未完成。

产品设计、技术验证与工程设计已经形成开发基线。后续实施继续遵守 [总计划](DEVELOPMENT-PLAN.md) 的阶段门禁；若应用需求必须修改未授权的 Atoll 核心能力，该路径立即停止。
