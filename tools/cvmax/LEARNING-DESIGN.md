# CvMax 学习主链设计 v3

> 2026-09-23：旧冷学习执行入口已删除；本文以下是待探索的新流程设计依据，不代表当前已接通。未知页面当前安全停在 `learning_unavailable`。

2026-09-12。状态：应用层实现及本地集成验证完成；真实站点覆盖与上线验收待完成。本文替代 v2 中关于学习、页面模型、Recipe 准入及复用的设计；现有接入、权限、任务控制与发布基础保留。本文不是运行能力声明。

## 1. 产品承诺

我们提前承担主要学习成本，用户享受成熟能力；线上自适应负责处理有限变化，不能把用户的一次填写变成长时间实验。

用户目标是将所选简历中有依据、页面能承载的内容完整填写并核验，不最终提交。用户通过现有 Skill/Client 委托；页面入口只有岗位详情和已打开的填写页。登录等确需参与的门槛一次只交接当前动作。页面专属缺项不阻塞已可完成的简历内容。无法访问后续表单时报告真实阻塞，不能宣称简历全部完成。

预学习使用明确授权的站点与测试资料，负责探索分支、形成映射、验证适用范围和发布公共能力；不意味训练基础模型参数，也不授予注册、认证、声明或提交的额外权限。用户线上运行遇到缺口，只在有限预算内适配，剩余问题记录为学习需求；不会自动把用户会话转为离线实验。

## 2. 不变量

- 所有代码限于 tools/cvmax/；复用 Atoll 身份、频道、消息、工具桥、资源及生命周期。需要改核心的路径停止。
- 外部宿主接待与资料准备；现有 Hosted Agent 负责解释和学习决策；应用工具持久化和校验；插件提供证据与受限动作。组件划分不要求增加 Agent 或服务。
- 一份简历一个事实单元；任务冻结所选简历 revision 和用户补充资料 revision。补充资料可以复用，简历之间永不互相补值。
- 任务、短租约、文档版本、停止闸门和未知效果核对继续生效。学习不能绕过 apply 的动作权限。
- 同一招聘系统可有多种合法结果；查询键是索引，适用条件和结果核验才是复用依据。
- 结构相同不等于无效果；结构变化也不自动证明业务成功。
- 本机知识和公共发布都要求证据准入；安装实例数量不能替代分支覆盖验证。

## 3. 统一主链

观察真实证据 → 解释当前情况 → 检索并检查知识是否足够 → 复用或学习缺口 → 执行受限动作 → 独立验证结果 → 更新知识 → 继续或交付。

学习步骤：明确未知问题 → 补充相关证据 → 提出候选解释与预期结果 → 检查允许的动作 → 执行一次 → 记录实际结果与反例 → 接受、修正或拒绝结论。

Recipe 是已验证知识的可执行产物，不是唯一学习记录。未知页面默认允许解释不完整，不强制归为已有页面类型。点击前必须记录观察基线和预期结果；点击后先识别发生的变化，再判断其业务意义。动画、广告、时间变化只能算噪声证据；出现相关新交互区域后，不重复原动作，先解释新区域。

## 4. 领域契约

所有对象有 schemaVersion、不可变 ID 和关联版本；持久化通过现有应用 Store 事务。完整原始证据只在私有任务作用域，公共经验为显式允许字段投影。

| 对象 | 必需内容 | 约束 |
|---|---|---|
| Observation | task/run/document、观察时间、URL/Tab、相关节点树、可见性/遮挡/焦点、采集范围与截断标记 | 证据不足不能推定没有变化；支持同作用域局部补采 |
| Interpretation | observationId、当前交互区域、字段语义、映射版本、未解释区域、支撑证据引用 | 语义映射是可修正解释，不是 Recipe 状态；未解释区域保留 |
| LearningEpisode | 目标、未知问题、预算、假设、前置条件、动作引用、预期结果、前后证据、判定与失败原因 | 追加事件保留修正链；不能只记成功轨迹 |
| KnowledgeCandidate | 系统范围、适用条件、组件映射、动作模板、可能结果、支持/反驳证据、覆盖范围 | 与运行中的 Recipe 分离；不能先复用再补证据 |
| Verification | 检验规则版本、证据引用、判定 passed/failed/unknown、覆盖项和限制 | 模型判断不是执行回执；回执不是业务结果 |
| RecipeRelease | 候选版本、编译版本、前置条件、动作、结果分支、证据覆盖摘要、签名和撤销状态 | 不包含简历值、任意可执行 JS、完整 DOM 或截图 |

观察先用紧凑摘要，未知时按需补采相关子树、布局及必要局部截图。输入值仅在私有填写核验所需范围读取；证据中其他个人信息、令牌和网页内嵌数据必须裁剪，不能仅靠删除 input.value 脱敏。公共投影需独立测试文本、属性、URL、截图引用的泄漏边界。

## 5. 映射与执行

页面映射学习范围包括交互区域、控件语义、字段区块和目标定位，不限于 add/section 别名。映射是受限声明式语义数据，解释器提供结构锚点、作用域、唯一性、可见性等通用操作。它只回答“这个页面元素对应哪条简历事实”，不回答“流程现在处于哪个状态”。映射修正不得改变同一结构动作的 Recipe 身份。

运行时只有 Recipe 拥有业务状态。Service 持久化当前 Recipe transition cursor，Operation 追加记录派发及回执，解析观察追加关联到发起上传的 Operation；不存在可以独立改写下一步的 Application workflow。上传后的覆盖确认是 Recipe 的后继页面状态与迁移，异步解析、服务重启和页面刷新仍在当前 transition settlement 内。学习只能补齐 Recipe 缺少的迁移，不得创建旁路填写流程。

已知路径仍逐步检查：粗粒度业务里程碑成立 → 当前动作的局部结构锚点唯一且该事实仍需处理 → 原子锁定 transition → 派发 → 浏览器回执 → 局部后置条件命中 → 紧接下一步。Recipe 不保存全页字段集合、字段语义 ID、字段值或任意网站问题作为流程身份。持久化执行游标严格经过 `locked → dispatching → settling → matched`；`timeout / gate / unknown / cancelled` 是显式出口。锁定和 operation 在同一事务中创建，因此不存在“浏览器已经接受动作、页面却暂时无人负责解释”的窗口。

浏览器 `accepted` 只证明动作请求被接收，不证明业务状态完成。字段动作以目标字段回读为局部后置条件；导航、上传和页面切换以对应业务表面或解析证据为局部后置条件。settlement 在回执后立即先观察一次；已经命中时零额外等待，否则才按短间隔有界重读。在限定时间内出现加载态、弹窗动画、局部重渲染、URL 变化或 document epoch 更新时，页面解释权仍属于当前 transition，不能把瞬时状态判为 Recipe 异常，也不能交给 Agent。服务重启从同一游标和剩余期限恢复，已经取得回执的动作不得重新派发。一个动作允许多个确定结果分支。对于已验证的申请入口动作，登录、验证码、简历前置页和申请表构成由 Service 定义的封闭合法结果集合；即使本次命中的是尚未记录的新分支，也应在稳定观察和动作效果核验后立即追加为候选分支并继续已有后继边。任意有文字弹窗、未知页面或仅有点击回执都不能借此成为合法结果。其他动作无法命中任何已声明分支时才转学习或停止。

岗位详情页若由 Service 从完整实时证据中确认恰好一个可命中、安全、非最终提交的申请入口，则 `run_recipe` 直接创建受控 LearningEpisode、执行一次并验证，不等待模型重新推导显然动作。被遮挡的规范节点只有在恰好一个同锚点可命中副本存在时才重绑定；其他歧义仍交给冷学习。入口后的新表单结构继续按正常冷学习处理。

本机候选必须先通过效果验证、锚点重绑定验证、适用条件检查才可编译为本机可试用 Recipe。预学习还需重新从声明入口执行验证；不得用同一快照重复判定充当独立复测。公共 release 额外要求覆盖矩阵、反例验证、隐私检查及现有签名发布流程。已有多安装统计保留为证据维度，不单独决定发布。

## 6. 验证和终止

执行结果区分：未派发、效果未知、确实无效果、出现新交互情况、预期业务效果确认。新 Tab 或文档更新本身不等于到达表单。字段结构没变但保留值正确可证明填写成功；禁止简单按 from==to 拒绝所有动作。

任务创建时从冻结的用户补充资料、本次所选简历和任务答案建立不可缩减的 ApplicationPlan，并为每个附件、事实和重复记录建立 ObligationLedger。Recipe 只描述无私有值的页面操作顺序，不能定义、覆盖或缩小业务范围；当前页面、关键字段和未来动作也不能反推应填范围。只有页面回读、原生解析事实匹配、完整区块观察证明无字段，或受控动作证明不支持，才能结算责任项。未访问区块和未处理事实保持 pending，不能以 partial 名义提前结束。

用户运行初始预算草案：已接受的未知实验从提出假设到验证结算累计最多 30 秒，同一缺口最多 2 个有不同证据依据的假设；预学习每个场景最多 10 分钟、同一缺口最多 3 个假设。实验预算跨恢复累计，Agent 排队/模型推理和等待用户不计入；Application 的独立 10 分钟活跃时间与 100 动作总预算继续约束完整运行，模型超时通过现有 Atoll 生命周期处理。预算边界已实现并有本地测试；真实使用体验仍需样本校准。

无新证据且重复同一动作意图时立即退出探索；未知效果只读核对，不点击探测。只有证明确未生效且前置条件重新成立才允许受限重试。任务停止优先于学习、编译和迟到回执。

## 7. 预学习与发布验收

每个招聘系统维护场景矩阵：详情/填写入口，已登录/未登录，已有/无简历，原生解析/自主填写，重复经历，弹窗/抽屉/局部切换，同 Tab/新 Tab，缺项与最终人工交接。并非每站都有所有分支；未发生或不可测试的明确标为未覆盖，不虚报。

预学习得到候选后，在重置的测试场景验证，随后用不同测试简历和另一岗位核验适用性；测试不最终提交。独立报告首访学习耗时与复用耗时、简历覆盖、错误写入、人工交接、无进展循环及版本更新次数。

上线门禁：声明支持的分支有证据；核心隔离/停止/不提交检查通过；同一插件和服务运行期间能加载新经验并完成未见过的目标场景；无法覆盖的浏览器能力明确报 unsupported。性能初始目标沿用已知流程 P50 8 秒/P95 20 秒，至少 20 个真实样本才判定；从页面打开开始计时，同时单列人工等待。

## 8. 工程组织

保留 client/atoll-client/install、browser-bridge、事实/附件隔离、Registry 的数据库访问/认证/签名传输基础。新建 observation、interpretation、learning、verification、recipe-compiler 的应用模块；由现有 service 调用，不建立第二调度器。public release schema 和插件证据协议分别版本化。

按模块替换旧路径，切换后删除不再调用的全页标准状态、固定稳定等待、即时轨迹发布和冲突判断逻辑；保留有效失败测试，不长期保留双学习入口。旧 Recipe format 不迁移，直接从本地缓存与 CvMax Registry 删除；数据清理不能影响 Atoll 核心库。

插件只在新增证据原语、协议不兼容或修复通用执行缺陷时升级；新增公司和学习映射仅发布数据。首次证据协议升级集中交付一次，再通过同版插件跨站验收验证这一边界。不能承诺以后永远无需升级。
